# Switchboard — Design invariants

> Visual & UX rules that must not be broken — read before any UI / CSS change. Lifted from the repo `AGENTS.md` (see its **Deep reference** index); normative. Every visual change must be authored and verified in BOTH light and dark themes — and, just the same, must support and be considered for BOTH agents (Claude Code and Codex). The two-theme and two-agent invariants are peers: a change that only works in one theme, or for one agent, is unfinished.

- **Two accent colors, each with one job.** Cobalt (`--live`, `#1F5AE6`) = a session is *alive*; the only *action* that may carry it is the one that brings a conversation to life — **Resume** (the pane header's button, and the conversation menu's Resume on hover, the live counterpart to Stop's red). A warm red (`--danger`, `#d8392c`) = *negative / destructive* (Stop controls, error states). Everything else — pins, selection, metadata — stays ink/graphite. **One sanctioned exception:** the rail's single white row — the focused pane's conversation, the one the keyboard acts on — is edged in **2px of cobalt**. It is `--live`, never `--dot`, so a chosen dot color never repaints it, and it marks exactly one row: the other pane's conversation says it is on screen through its own tab, because two edged rows would read as two selections. **Cobalt is the DOT's default, not its only possibility**: Preferences → Beta Features → **Liveness dot color** recolors the liveness dot and only it — every dot state, plus the ⋮ menu's read/unread dot and the title-bar bell's, which are spec'd to read identically. It is its own token (`--dot`, which follows `--live` until a color is chosen), so the selected row's edge, Resume and the brand marks stay cobalt; recoloring `--live` would be a palette change rather than a dot. A chosen color is placed by a contrast solve against the surface it sits on (`lib/dotColor.ts`), never shown as picked when that would take the dot under 3:1 — a 7px disc, or a 1.5px hollow ring, is a signal before it is a color. It adds no hue: `--dot` carries the same one job. The invariant holds in **new chrome too**: the Updates control in Preferences is strictly neutral (ink / paper / gray) — no cobalt, no red — including the **update-available attention dot** on the title-bar gear + the Application nav row, which is a neutral **ink** dot, not a colored badge (an update is neither *alive* nor *destructive*); and the ⋮ menu, folder headers, the new-conversation chooser, and settings buttons all stay grayscale. **Hover is a fill, never a lift:** a resting row takes `--rail-hover` and the white row `--rail-selected-hover` — separate tokens because dark's shared `--paper-hover` is brighter than `--paper-raised`, which would make a hovered row outshine the selection. Selection and hover **snap**: easing the white in and out reads as selection lag on every arrow key and click.
- **Rows: one line by default, and nothing moves when their state changes.** The whole rail renders through `ConversationRow`, so a row's cost multiplies across every row. **Compact** (the default) is one line — agent logo, title, and the dot in the right gutter — with the preview, folder and last activity in the row's hover; **Spacious** shows the preview and a meta line inline. Compact draws no divider lines at all; Spacious draws an inset hairline between two resting rows, which yields to any row carrying a fill (a hovered row, the white row). A pinned row carries a small filled pin ahead of its title — an indicator, not a control. A conversation that **needs you** (asking, or finished and unread — the one `needsYou` predicate behind the bell, a folder's name and a row's title, so the three always agree) goes heavy in its row, its folder's name and its tab. Weight is the only cue, and it shifts nothing: a row title truncates, and a folder name or a tab title stacks a hidden bold copy under the visible one, so its cell is always as wide as the bold.
  - **The gutter dot** shows a live row's turn-state (everything else is blank): **breathing** = a turn is in progress · **a ripple** (rings pulsing outward from a briefly-swelling dot) = the agent is blocked on your reply (an AskUserQuestion / ExitPlanMode, or a Codex approval, unread) · **solid** = the turn finished and you haven't viewed it since (unread) · **hollow ring** = finished and already seen (up to date). The solid/unread state can also be set **by hand** (`⇧⌘U`, **⌥-click** on a live row, its tab or its terminal, or the ⋮ menu — see the Liveness model in [architecture.md](architecture.md)). Rows with no linked conversation are the deliberate exception: a provisional new-Codex terminal before its rollout binds, and a Claude terminal whose work went into a background agent rather than its own transcript. Neither has a resolved liveness state, and both share the hollow ring because neither has unread conversation content — the semantic distinction is carried by the `unlinked` accessibility label, not by a bespoke marker. The parked-agent row additionally titles itself with the agent's name and says `Terminal only — work is in a background agent` where a preview would go, because unlike a pending first turn its emptiness is permanent and needs explaining.
  - **One conversation menu, reached three ways.** Hovering a row swaps its dot for a ⋮ button; that button, a right-click on the row, and a right-click on the conversation's tab all open the same list (`lib/conversationMenu.ts`), in the same words and the same order — Resume · where it shows · pin, read/unread, rename, details · (on a tab) close · Stop, red and last. **Menu icons reflect the END state**: an unpinned row shows a **filled** pin (the state the click produces), and the read/unread item shows the dot it will leave behind — spec'd like the liveness dot, gray at rest, cobalt on hover. The rail's menu **fades out on close** (~420ms), and **auto-closes after ~1.5s un-hovered** — but **never while the pointer is over it**.
  - **No inline Stop.** A live session is ended by the **Stop** button in the pane header, or the menu's **Stop session**.
  - **Pane header cluster:** keeps its own pin on the **left**; there the **Terminal** view-toggle carries a **static solid cobalt dot** — it marks that the session is live and does not encode turn-state. The breathing/ripple liveness animation lives on rows, tabs and the bell.
- **The rail orders by stable keys, never by activity.** A row nobody has moved ranks at its **seed** — when its conversation started (`firstActivityAt`; the file's birth time, then `mtime`, only as fallbacks) — newest first; a terminal the index has not listed yet ranks at its terminal's start. Only four events store a position, each writing one key (`lib/rowRank.ts`): a **drag** writes the dropped row's rank; **Resume** lifts its row above every unpinned row, in every folder and in All at once, and never behind the clock, so a conversation started after the Resume still lands above it; a placeholder terminal **binding** to its real conversation hands its rank to the real id; and a new conversation's **first index** keeps the rank its stand-in row had, in the same build, so it never jumps. Output, turn-state and file writes never move a row. Ranks are timestamps in one global space, so a drop inside a folder also places the row consistently in All mode. **Folders** order the same way, seeded by their earliest conversation, which is fixed once seen; the first time a profile runs this rail the folders it already has are frozen newest-first, once. **Pins** sit above the rest of their folder (or of All) in the user's own order, and a new pin lands at the end — a user action, not activity. When a row does move — pinned, unpinned, dropped — it **glides** to its new place (`useRailFlip`, compositor-only), and a new row fades in; search, collapse and Show more stay instant.
- **Each folder shows its latest few, by position — never by liveness.** A folder shows at least 5 rows and at least 3 unpinned ones; All mode shows 40. Pins always show and count toward the cap, so unpinned rows shown = max(3, cap − pins) plus whatever **Show more** has revealed (**Show less** takes it back; neither carries a count). Rows past the cap that are **live or on screen still render**, after the capped run, so a running conversation is never hidden by its position — while whether an idle row shows never depends on another row's liveness. A drop never hides the row dropped. Searching expands every folder and lifts every cap. Folders past the first **8** start collapsed, decided **once per launch** from that launch's order, so a folder arriving at the top or a folder drag collapses nothing mid-session. A collapse the user sets persists, and a folder opens for the conversation that is active in it until the user collapses it again.
- **Folder headers are quiet, sticky, and never reflow.** A header is a chevron, the folder's name — its basename, widened by parent segments only where two would read the same — and, while the pointer is in the folder, a pencil (a chooser on that folder) with the installed agents' logos sliding out from under it (that agent, started there at once); ⇧-click either for a new window. It sticks while its folder scrolls under it, painting the rail's own surface with a short fade below it only while stuck, and un-sticks when its folder scrolls away, so the folder you are in is always named. Its name's hover fill is `--rail-hover`, like a row's.
- **Drag to arrange: rows within their block, folders among folders.** A block is a folder's pinned rows, its unpinned rows, or one of All mode's two lists; dragging never moves a row between blocks (pin and unpin do). The grabbed row or folder lifts into a `position:fixed` clone on `<body>`, carrying the rail's own classes so it looks exactly as it did in place, so it floats over the head and the sticky headers instead of being clipped by the rail body's overflow. Its siblings slide to open the gap, the order changes only on drop, and the clone eases into the slot as it lands. A dragged folder **folds to its header** for the drag, so it moves as one short card, and opens again where it lands. Resting the pointer in the list's top or bottom band autoscrolls it (the tab strip's band and speed), and the wheel scrolls under a drag without anything going stale. Escape cancels, and so does anything that reshapes the rail mid-drag — mode, density, search, or a re-index that moves the block.
- **An empty conversation's tab and its terminal end together.** A conversation with no messages has no row of its own — the rail shows it only while its terminal lives — so the user's Stop closes its tab, and closing its tab stops it. Only when nothing would be lost: nothing indexed or written to disk, no background agent, and **nobody has typed into it** — a typed-into terminal may hold a draft not yet sent, so closing its tab leaves it running for its own Stop. A terminal that exits on its own keeps its tab, since what it printed on the way out is worth reading, and Back/Forward step over a conversation that ended having written nothing.
- **Single-family type:** Hanken Grotesk for UI + display (heavy weights carry the display moments); IBM Plex Mono for the terminal + mono metadata. No serif. (One narrow exception: keyboard-shortcut glyphs — `⌘ ⇧ ⌥ ⏎ ↑ ↓` — render in `--font-keys` = the macOS system font, which carries them at consistent size/baseline; Hanken & Plex lack several and fall back per-glyph, which looked small/off-baseline.)
- **Preview ≠ spawn:** selecting a conversation only previews it (read-only, from the JSONL). A live agent process is created ONLY by explicit **Resume** or **New** — the chooser, or a folder's agent logo.
- **A conversation appears in exactly one place.** One tab, app-wide — not one per pane, not one per window. Opening a conversation that is already open **reveals** the tab it has (focusing that pane, and that window) rather than making a second; only an explicit placement — Split Right, Move Right/Left, Open to the Side, a drop — moves it. Two tabs for one conversation is not a cosmetic duplicate: it forces the app to nominate one of them for ⌘W, for the liveness dot, and for where a reveal lands, and every answer is wrong somewhere. A row whose conversation lives in another window says so, because a click that raises a different window is startling when nothing warned you.
- **The tab strip is chrome, and stays neutral.** It sits on `--paper-sunken` like the title bar and the rail; the active tab lifts onto `--paper-pane` — the surface directly beneath it — so tab and pane read as one sheet. Selected-ness gets **no accent**: cobalt means a session is alive and red means destructive, and "this tab is active" is neither. Which pane holds the keyboard is carried by ink alone — full ink on the focused pane's active tab, faint on the other pane's, the same one-conversation answer the rail gives with its one white row; a bar along the tab's edge would be a slab at a tab's width, and read as chrome in its own right rather than as an attribute of the tab. A tab whose conversation needs you goes bold without moving, and holding ⌥ turns a running tab's × red: stop and close. Tabs **wrap into as many rows as needed by default**, without a row cap or vertical scrollbar. **Tab layout → Scroll** instead keeps one horizontal row with no scrollbar; fixed edge fades indicate hidden tabs, using the rail’s surface and fade timing while preserving square edges and the bottom rule. Selecting a tab keeps it visible in either layout; manual scrolling may leave it offscreen. Every tab permanently reserves a compact **10px** liveness/close slot after a **6px** title gap, with **8px** right padding; the 17px close target is centered over that slot, so liveness never changes the tab or title width. One shared layer paints a native 1px CSS border across each measured row bottom, spanning tabs and empty space above every fill. Using the same border primitive as the vertical dividers keeps their weight consistent at fractional zoom; a repeated gradient band does not.
- **The pane header sheds content in stages, and never wraps.** Both panes' headers are a **fixed height**, so they align by construction rather than by their contents happening to measure the same. Nothing in the header may reflow: text truncates, or a stage drops it. The stages run against the **pane's** width: Formatted/Terminal labels collapse at 840px; Resume/Stop become 30px icon circles at 700px; path and branch leave at 520px; Find and Pin leave last. In split view, the view toggle and Resume/Stop always use their compact forms, regardless of pane width. An open Find bar starts earlier because it adds another wide control: the view toggle collapses at 900px and Find replaces the title below 760px. Every removed label retains a tooltip and explicit accessible name, so narrowing costs legibility and never function.
- **Formatted view is read-only** (rendered from the JSONL); typing happens in the **Terminal** view. The selected Formatted/Terminal surface and each Formatted reading position are session-local per conversation and survive navigation; preserve that without retaining hidden Markdown trees. Formatted is also the surface for **find-in-conversation** (`⌘F` when the main pane is focused) — and searches human and agent messages, including their code blocks. Tool sections (summaries, names, arguments, and results) are excluded whether collapsed or expanded, along with transcript chrome and hidden LaTeX source. Search never opens or expands tool content. **Closing the find bar (Esc / ✕) leaves you at the current match** — it does not snap the scroll back to where you opened search. The Formatted view also carries **jump-to-edge pills** (**Jump to top** / **Jump to bottom**) — center-aligned, **Hanken** text plus an arrow glyph, each shown **only when scrolled away from that edge** (top pill hidden at the top, bottom pill hidden at the bottom) and jumping with an **instant snap**, not a smooth scroll. They stay strictly neutral (ink / paper / gray) per the two-accent rule.
- **Transcript rendering coalesces into same-author *sections*, one header each.** `lib/messageGroups.ts#buildRenderItems` turns the lines into `RenderItem`s — prose **turns** (You / Claude / Codex text), collapsed **tool runs**, and the interrupt note — then `groupSections` bundles consecutive same-author items under a **single header** (`buildTranscript` composes both; `TranscriptView` maps `MessageBlock` over the sections, memoized on the transcript so search re-renders keep the memo). So a stretch of Claude narration + its tool activity shows **one `Claude` header**, not a header per beat. The header is a **filled tag** (a `--paper-hover` chip, Title-case Hanken at body size, `--ink-soft`) with a leading mark — the agent **logo** (`AgentLogo`, ink) or a **person** glyph for You. **Attribution is by content, not raw role:** the parser tags each `user` line `userKind` — `human` (typed prompt → "You"), `tool_result` (tool output → folded into a **tool run**, never "You"), or `interrupted` (the Esc sentinel → a centered muted note); non-conversational `user` lines (slash-command echo, `isMeta`, task-notifications) **and thinking blocks** are dropped at parse time. A single hairline rule separates a **You** (human) section from the surrounding agent section — drawn ONLY at that You↔agent boundary, never within a section (`.message.has-divider`, computed in `TranscriptView` as `dividerBefore`). **You and agent prose share one Markdown renderer** (`MarkdownBlock`), so user-authored bold, headings, lists, links, tables, inline code, and fenced code receive exactly the same styling and syntax highlighting as agent prose. The shared block rhythm keeps general top-level transitions at 22px, tightens paragraph↔paragraph and paragraph↔list boundaries to 16px, and sizes each heading tier 1px above its former token; Formatted-view links expose their URL in a wrapping compact tooltip and open through `window.api.openExternal`. **Tool activity collapses into runs:** a maximal run of consecutive `tool_use` + `tool_result` (crossing assistant-message boundaries; broken only by prose, a human turn, an interrupt, or a main↔sidechain switch) hides behind ONE disclosure — a chevron + a bold **`N tool calls`** count, a native (uncontrolled) `<details>` so the toggle is browser-instant (open-state is tracked only to word the tooltip); its contents mount on first open, in the same frame. Expanding lists each call (**`⚙ Name`** + its input JSON) paired by id with its output (a quiet **`↳ Result`**, or red **`↳ Error`**) over the sunken block; a pending call reads *Awaiting output…*. There is **no standalone Result/Error header** — results live inside their run. A long result clamps to **6 rendered lines** with a bottom fade; only a bottom **hot-zone** (≈ the fade height) hovers/clicks (the rest of the block stays selectable / I-beam), revealing a centered **`Expand ↓` / `Collapse ↑`** + an ink scrim and toggling the clamp. An **error result keeps its red box**. Each section header carries a quiet right-aligned timestamp (`format.ts#clockTime`; full date/time on hover via `data-tip`); the tool-run header carries none. Code/mono surfaces sit at the **terminal size** (`--text-xs`). **Copy affordances** use the shared neutral `CopyButton` with a check-flash. Turn and whole-conversation copies include prose and image labels, exclude tools regardless of disclosure, and preserve complete Markdown when enabled. The footer export includes speaker attribution and unmounted content. Code/JSON/result buttons copy complete bare payloads, including clamped content; table buttons preserve the complete table in the chosen format. Selection-copy has a separate contract: outer formatting requires complete coverage plus selected non-whitespace content beyond either end, with each nested style evaluated independently. Multi-item lists preserve structural markers; tables preserve row/column structure; formulas are atomic LaTeX. Selected whitespace stays intact; spaces at generated formatting boundaries may move outside the markers to keep the Markdown valid. Trailing selected breaks remain literal newlines even when a Markdown destination hides the final empty lines. Adjacent code spans and formulas keep their separate payloads without inserted whitespace. Non-whitespace styling is preserved, and selections never expand to recover uncertain formatting. Mixed Markdown passages escape literal punctuation consistently and may encode neighbouring characters as numeric references to keep generated delimiters valid; bare-only passages remain literal. If Markdown serialization fails, the whole selection quietly uses semantic plain text, preserving visibility rules while dropping otherwise eligible formatting. Native copying never takes over a handled transcript selection. See [architecture.md](architecture.md) for the complete copy rules. Buttons carry no searchable text and remain fixed outside horizontally scrolling payloads. Both themes and agents share this behavior.

- **Nothing highlights that a copy won't deliver.** The transcript opts into `user-select: text` against the global `body` `none`, and everything that is chrome rather than content opts back out: the speaker tag, the Sub-agent tag, the timestamp, the transcript footer, the Expand/Collapse label, *Awaiting output…*, the Interrupted note, the fenced-code language caption, decorative image glyphs, footnote return arrows, and the `⚙`/`↳` tool heads. The rule is about the PROMISE a highlight makes — a drag that sweeps up a timestamp and then omits it from the paste is a small lie. Attribution and the tool labels still reach the clipboard, but as text *generated* from the section's `data-speaker`/`data-sidechain` and the tool name (`Bash:` / `Result:`, glyphs dropped), never lifted from those elements — which is exactly why they can stay unselectable. The inverse case is fine and normal: generated structure like `**You:**` and the `---` rules was never highlighted either.
- **Every scrollbar hides at rest and reveals on scroll — horizontal ones included, at one weight.** The single-row tab strip is the explicit exception: it never shows a scrollbar and uses edge fades instead. A bar is chrome, so it earns its space only while it is being used: `.sb-autoscroll` + `--bar-thin` is the single spec for the rail, the new-conversation chooser, and every scroller in the transcript, and the plain arrow (not the i-beam) belongs over all of them. Two traps this invariant is built out of, both in `global.css`: set the revealed color with `background-color`, never the `background` shorthand, which resets `background-clip` and paints the thumb over the transparent border that gives it its inset; and a block that reserves a strip for a horizontal bar must subtract `--bar-thin` from its own padding, or it reads taller and bottom-heavy next to a block that doesn't scroll. The **inline-axis counterpart is the rail's deliberately lopsided padding**: `scrollbar-gutter: stable` reserves the strip at one edge only, and the overflow clip edge sits *inside* that strip, so no descendant can paint there — the padding is the only room anything may paint outside a row (the white row's 2px edge, a folder header's hover fill). `.sb-rail-body` therefore pays `--rail-inset` on the scrollbar side and `--rail-inset + --bar-thin` on the other, which is what lands a row's two edges the same distance from the rail's edges. **Even padding there renders visibly off-center**, so symmetric values in that one rule are the bug, not the fix. The head sits outside the scroller and so aligns to `--rail-text-inset` (the text column) instead, which keeps its controls in line with the rows beneath them.
- Design tokens live in `src/renderer/styles/tokens.css` — reuse the CSS vars; don't hardcode colors.
- **Two themes, one source of truth — a hardcoded color is a dark-mode bug, and EVERY visual change must be authored + verified in BOTH themes.** `tokens.css` defines a **neutral grayscale** light palette in `:root` and a **neutral near-black** dark palette in `:root[data-theme='dark']` (only color + shadow tokens are overridden; type/spacing/radii/motion/layout are shared). Surface tokens: `--paper-sunken` = **chrome** (the rail AND the title bar — `.sb-titlebar` uses `--paper-sunken`, not `--paper`, so they read as one continuous chrome), `--paper-pane` = **main content** (pane / Formatted / terminal), `--paper-raised` = **raised tiles** (the rail's one white row, modals, menus), `--paper` = the field/shell behind them, `--paper-code` = the **unified mono surface** for fenced + inline code AND tool result/JSON blocks (light `#f6f6f6`, midway between the rail and the pane; dark `#1c1c1c`, recessed a step below the pane — so all mono output reads as one surface, set apart from both). **Dark keeps light's elevation order**: the pane (`--paper-pane`, `#212121`) sits above the chrome (`--paper-sunken`, `#191919` — the rail and the title bar), mono surfaces recess a step below the pane, and raised tiles (`--paper-raised`, `#2a2a2a`) sit above both. The terminal's dark background tracks the pane (`TerminalView` repeats the value — move the two together), and the window's pre-paint color follows `--paper`, so neither reads as a hole. **Hairlines are scoped per surface in dark:** `--rule` / `--rule-soft` mean "a hairline on the surface it is drawn on", and a token carries hue across themes but not the lightness step that makes a hairline visible — light's surfaces all sit within a few steps of white, while dark's climb from chrome to pane to raised — so each dark surface above the chrome (the pane, the settings page, modals and menus) sets its own pair, matched to light's step on white. A new dark surface with hairlines inside it gets its own pair in `tokens.css`. Every surface paints from a token, so dark mode is "free" for any component that obeys this — **but "free" covers hue, not feel.** A token flips the *color* per theme; it does NOT carry perceptual *strength* across the light↔dark luminance gap, so any change with a visual dimension (shadow alpha, opacity, contrast, glow) must be **eyeballed in BOTH themes**, not just authored in one. The breathing dot's halo is the plainest case: `--dot` at one alpha over a near-black row carries about 58% of the presence it has over a white one, so `--dot-halo` is theme-aware (0.22 light, 0.35 dark) — the alpha rises rather than the color lightening, which keeps the halo the dot's own hue now that the dot can be user-chosen. `--shadow-sel-hover` is the same lesson with a twist: a *low-alpha* black drop shadow is **invisible** on a near-black surface, so the token keeps one geometry but **boosts the alpha to near-opaque in dark**, where an opaque black darkens toward #000 and reads (light keeps the soft low-alpha black). The cobalt **Resume** button's hover lift uses it. "I changed a visual and only looked in light" is unfinished work. The **two-accent invariant holds in both themes**: cobalt = alive, red = destructive (both brightened for dark, soft/wash tints dark-tinted); pins/selection/metadata stay ink. **The ONE sanctioned exception to grayscale-plus-two-accents is syntax highlighting** — the Formatted view's fenced code blocks carry a full-color syntax palette (highlight.js `.hljs-*` token colors, themed per light/dark in `transcript.css`) — the **GitHub** palette (`github.css` / `github-dark.css`) ported onto our own fence surfaces (we keep `--paper-code` + `--ink`, swapping only the token hues). It carries a **per-language exception**: YAML keeps the prior muted One-Light/One-Dark palette, scoped by a `data-lang` stamp on `.md-pre-wrap` (set in `MessageBlock.tsx` from `codeLang.ts`, which folds `yml`→`yaml`) — so future per-language exceptions are a small scoped block, not new plumbing. This is the only place any hue beyond cobalt (liveness) / red (errors) appears, and it appears ONLY inside `.hljs` code — a deliberate, tightly scoped exception, not a loophole; nothing outside fenced code may introduce a third hue. (The fenced block's **language caption** — the `.md-lang` caps-label in its top-left gutter — is itself **neutral grayscale**, so it is NOT part of this exception, just an ordinary ink element sitting near the colored code.) One-off shadows use the `--shadow-color` channel (`rgba(var(--shadow-color), α)`) and overlays use `--scrim`. The Preferences modal mirrors these surfaces (chrome head+nav, content page — see the Preferences pointer in [architecture.md](architecture.md)); its **settings buttons are a light gray `--btn`, never white** — and "lighter" is **not one shared value**: light mode's `--btn` is a hair off white, dark mode's is a readable gray, each picked per-theme rather than reused. The active theme is a JS-resolved `data-theme` on `<html>` (System/Light/Dark), **never** a bare `@media (prefers-color-scheme)` — so explicit Light/Dark beats the OS. Preferences → Appearance also exposes a **dark dock-icon toggle** (Light / Dark) that is **independent of the app theme** — it picks which dock-icon variant macOS shows, and does **not** follow (or change) the Light/Dark UI choice; the two are orthogonal settings. See the **Theming** pointer in [architecture.md](architecture.md).
- **Two agents, one experience — every change must support BOTH Claude Code and Codex, exactly as it must both themes.** Switchboard browses conversations from both agents in one unified list; a feature that only works for one is unfinished, the same way a hardcoded color is a dark-mode bug. Everything keys off `ConversationMeta.agent` (`'claude' | 'codex'`): the list, transcript, liveness dot, **resume / new**, **rename**, and the info modal all branch on it. Claude reads `~/.claude/projects/` JSONL; Codex reads `~/.codex/sessions/` rollouts (plus its `state_*.sqlite` + durable `session_index.jsonl` for titles). Resume types `claude --resume <id>` vs `codex resume <id>`; rename appends Claude's own `custom-title` line vs calls Codex's app-server `thread/name/set`; tokens render **per-agent** categories and are **never unified**. The `AGENTS` registry (`shared/types.ts`) carries each agent's label + logo, surfaced by `AgentLogo` — and **logos are ink (`currentColor`), never an accent**, so they obey the two-accent invariant and track their text. The seam is the **main-process agent split** (`sessions/{parser, codexParser, codexThreadsDb, codexSessionIndex, rename, codexRename}`, the dual-root `indexer`/`watcher`, and a per-agent boot command in `pty/manager`); the renderer consumes a **normalized** transcript/meta contract so rendering stays agent-agnostic. When you add or change anything, ask "does this hold for Codex too?" and verify both — exactly like light/dark. See the **Multi-agent (Codex)** pointer in [architecture.md](architecture.md).
