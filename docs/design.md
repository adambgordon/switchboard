# Switchboard — Design invariants

> Visual & UX rules that must not be broken — read before any UI / CSS change. Lifted from the repo `CLAUDE.md` (see its **Deep reference** index); normative. Every visual change must be authored and verified in BOTH light and dark themes — and, just the same, must support and be considered for BOTH agents (Claude Code and Codex). The two-theme and two-agent invariants are peers: a change that only works in one theme, or for one agent, is unfinished.

- **Two accent colors, each with one job.** Cobalt (`--live`, `#1F5AE6`) = a session is *alive*; the only *action* that may carry it is the one that brings a conversation to life — the right-click **Resume** (cobalt-on-hover, the live counterpart to Stop's red). A warm red (`--danger`, `#d8392c`) = *negative / destructive* (End/Stop controls, error states). Everything else — pins, selection, metadata — stays ink/graphite. The invariant holds in **new chrome too**: the Updates control in Preferences is strictly neutral (ink / paper / gray) — no cobalt, no red — including the **update-available attention dot** on the title-bar gear + the Application nav row, which is a neutral **ink** dot, not a colored badge (an update is neither *alive* nor *destructive*); and the ⋮ row-menu, sidebar headers, and settings buttons (below) all stay grayscale. **Selection is a single tier** — the main pane always owns the keyboard, so there's no list-focus state: the selected row carries its color as a thin **1px ring**, **cobalt** for a *live* one and neutral gray/ink for the rest (cobalt stays liveness-only, so a cobalt ring = the selected conversation is live), with **no drop shadow or lift**. Mouse-**hover** keeps its own card lift — the theme-aware `--shadow-sel-hover` token: in **light** a soft low-alpha dark drop shadow, in **dark** the *same geometry* at near-opaque black (a *low-alpha* black vanishes on the near-black rail; an opaque one reads) — and it is **clipped on three sides** by `.sb-rail-body`'s `overflow`, so its reach is a budget rather than a free choice: 7.5px sideways against `--rail-inset`, 4.0px up against `padding-top`, 11.5px down against `padding-bottom` — clearances of **−0.5px, +2.0px and +0.5px** respectively, the side being an accepted overshoot. `rail.css` holds that table and deliberately names no edge "the tightest," because which one that is flips whenever a budget moves. Only the **section** order is guaranteed (Pinned and Live precede Recent) — inside Pinned the order is the user's and card chrome is per-row, so a live card can sit anywhere, last included. `padding-bottom` therefore covers one case only, a hovered card at max scroll: at any intermediate scroll the clip falls wherever the viewport ends, and the rail's bottom fade does **not** hide that, because the `:hover` rule supplying the shadow also sets `z-index: 1` and outranks the fade. That `padding-top` trades against `.sb-rail-head`'s bottom padding (the pair must sum to 10px or the first row moves), so buying shadow clearance there costs divider breathing room in the head. **Light is the binding theme** for all three budgets (see the scrollbar bullet below), and none of them has automated coverage — the figures are one-off measurements, so a change to this token or those paddings is unverified until re-measured; the selected/hovered row is `z-index:1` so that lift paints over neighboring live cards. (The old focus-tiered *loud* selection shadow and its `--shadow-sel` token were removed when list-focus went away.)
- **Row controls live in the right gutter.** In the left pane's rows, the liveness indicator and the pin toggle share one right-hand slot.
  - **At rest, a live row shows a cobalt marker** (everything else is blank). For a linked conversation, its form encodes turn-state: **breathing** = a turn is in progress · **a cobalt ripple** (rings pulsing outward from a briefly-swelling dot) = Claude is blocked on your reply (an AskUserQuestion / ExitPlanMode, unread) · **solid** = the turn finished and you haven't viewed it since (unread) · **hollow ring** = finished and already seen (up to date). The solid/unread state can also be set **by hand** (`⇧⌘U`, **Option+click** on a live row, or the row's ⋮ menu — see the Liveness model in [architecture.md](architecture.md)). Rows with no linked conversation are the deliberate exception: a provisional new-Codex terminal before its rollout binds, and a Claude terminal whose work went into a background agent rather than its own transcript. Neither has a resolved liveness state, and both share the hollow ring because neither has unread conversation content — the semantic distinction is carried by the `unlinked` accessibility label and its own tally bucket, not by a bespoke marker. The parked-agent row additionally titles itself with the agent's name and says `Terminal only — work is in a background agent` where a preview would go, because unlike a pending first turn its emptiness is permanent and needs explaining.
  - **The ⋮ row menu replaces both the pin icon and the old right-click menu.** A hover-revealed ⋮ button in the gutter opens the row's actions (pin/unpin, mark read/unread, Resume, Stop, rename, …) in one place — left-click only; there's no separate context menu. **Menu icons reflect the END state**, not the current one: a row that's *not* pinned shows a **filled** pin labeled "to pin" (the state the click produces), and the read/unread item shows the dot it will leave behind. The menu **fades out on close** (~420ms) rather than vanishing, and **auto-closes after ~1.5s un-hovered** — but **never while the pointer is over it** (the timer only runs once you leave). The menu's **read/unread dot is spec'd identically to the liveness dot** — gray at rest, **cobalt on hover** — so the same affordance reads the same everywhere (and stays inside the two-accent rule).
  - **No inline Stop.** A live session is ended by the **Stop** button in the pane header, or the live row's ⋮ menu → **Stop session**.
  - **Pane header cluster:** keeps its own pin on the **left**; there the **Terminal** view-toggle carries a **static solid cobalt dot** — it marks that the session is live but no longer encodes turn-state. The breathing/ripple liveness animation lives only on the left-pane rows.
  - **Drag-to-reorder (Pinned and Live, always on).** Each section reorders within itself via `useRowReorder` — one instance per section, partitioned by CSS selector (`.sb-row.pinned` vs `.sb-row.live:not(.pinned)`, so a pinned-live row is owned by the Pinned instance). The moving card is a `position:fixed` clone on `<body>` so it floats over the head instead of being clipped by the rail body's overflow; its vertical travel is **clamped to a partial overshoot** past its section (≈ half a row — the card's center can't leave the section), not free. Siblings slide live to open the drop gap (fixed section height); on drop the clone eases into its slot *while* dropping out of the lifted look at the same time, so release reads as one motion, not a slide-then-snap-flat.
- **The pane orders by stable keys, never live activity.** Rows hold position by pin order (**Pinned**) and a **manual order** (**Live** — every newly-live session, new or resumed, lands on top, and you drag to reorder; held in `useLiveOrder`, ephemeral) — never `lastActivity` — so a session emitting output never makes a live row jump (regression fixed in `ce407fa`; the manual order now makes this structural — Live no longer auto-sorts by `startedAt` at all, a row holds its slot until you move it). The **Recent** section is the deliberate exception: a recency history of *not-live* conversations, sorted by `mtime`. Pinning a row appends it to the **end** of **Pinned** (`usePins.toggle` is `[...prev, id]`; drag to move it) — a user action, not activity. **The whole pane renders through `ConversationRow`** — the unified left pane *is* the left column now (no separate sidebar): card chrome (`.sb-row.card`) marks **live rows only** (a white card = a live session, so a non-live pinned row renders flat like Recent), and Pinned/Live add the live click-to-jump; the pin-on-hover gutter toggle is a shared `.sb-row` primitive, so it (and the liveness dot) work on Recent's flat rows too. The three sections are individually collapsible, and **Recent** is capped (30) with a *Show more* reveal at the bottom. So `ConversationRow` changes flow into every section. When a row *does* change section — pinned, resumed, or unpinned — it **glides** to its new position via a FLIP animation (`useRailFlip`) instead of teleporting; the old `sb-patch-in` entrance keyframe was retired (it re-fired when a row gained `.card` in place, collapsing then re-expanding a resumed pinned row — the "delete + re-add" flicker), so a row going live just eases its card *background* in. `border-color` and `box-shadow` are deliberately **not** transitioned on `.card` rows, so the selection ring (`.selected`, a single thin 1px tier) is **instant** on select *and* deselect — matching the flat rows, which snap the same way; transitioning them made the ring linger ~120ms (an expo-out tail) when you switched to another conversation. (Card hover snaps too, as a consequence — consistent with the rail's flat rows.)
- **Sidebar section headers (PINNED / LIVE / RECENT) are quiet, not loud.** Each header carries a **1px `--ink-ghost` leader rule** — a lighter-weight line in a **higher-contrast color than the `--rule` grays** (darker than `--rule` on light, lighter on dark — so it gains contrast in *both* themes rather than fading at one end). The section **labels themselves are Hanken** (`--font-ui`), **not** the mono `.label-caps` treatment used elsewhere: normal letter-spacing, size `--text-xs`. Between rows, **lightweight inter-row dividers** separate adjacent rows that are *not* live, *not* selected, and *not* hovered — so the chrome of cards / selection / hover always wins and the dividers only quietly stitch the flat resting rows.
- **Single-family type:** Hanken Grotesk for UI + display (heavy weights carry the display moments); IBM Plex Mono for the terminal + mono metadata. No serif. (One narrow exception: keyboard-shortcut glyphs — `⌘ ⇧ ⌥ ⏎ ↑ ↓` — render in `--font-keys` = the macOS system font, which carries them at consistent size/baseline; Hanken & Plex lack several and fall back per-glyph, which looked small/off-baseline.)
- **Preview ≠ spawn:** selecting a conversation only previews it (read-only, from the JSONL). A live `claude` process is created ONLY by explicit **Resume** or **New**.
- **A conversation appears in exactly one place.** One tab, app-wide — not one per pane, not one per window. Opening a conversation that is already open **reveals** the tab it has (focusing that pane, and that window) rather than making a second; only an explicit placement — Split Right, Move Right/Left, Open to the Side, a drop — moves it. Two tabs for one conversation is not a cosmetic duplicate: it forces the app to nominate one of them for ⌘W, for the liveness dot, and for where a reveal lands, and every answer is wrong somewhere. A row whose conversation lives in another window says so, because a click that raises a different window is startling when nothing warned you.
- **The tab strip is chrome, and stays neutral.** It sits on `--paper-sunken` like the title bar and the rail; the active tab lifts onto `--paper-pane` — the surface directly beneath it — so tab and pane read as one sheet. Selected-ness gets **no accent**: cobalt means a session is alive and red means destructive, and "this tab is active" is neither. Which pane holds the keyboard is carried by ink weight alone; it was briefly a bar along the tab's top edge, and at a tab's width a bar is a slab that reads as chrome in its own right rather than as an attribute of the tab. Tabs **wrap into as many rows as needed by default**, without a row cap or vertical scrollbar. **Tab layout → Scroll** instead keeps one horizontal row with no scrollbar; fixed edge fades indicate hidden tabs, using the rail’s surface and fade timing while preserving square edges and the bottom rule. Selecting a tab keeps it visible in either layout; manual scrolling may leave it offscreen. Every tab permanently reserves a compact **10px** liveness/close slot after a **6px** title gap, with **8px** right padding; the 17px close target is centered over that slot, so liveness never changes the tab or title width. One shared layer paints a native 1px CSS border across each measured row bottom, spanning tabs and empty space above every fill. Using the same border primitive as the vertical dividers keeps their weight consistent at fractional zoom; a repeated gradient band does not.
- **The pane header sheds content in stages, and never wraps.** Both panes' headers are a **fixed height**, so they align by construction rather than by their contents happening to measure the same. Nothing in the header may reflow: text truncates, or a stage drops it. The stages run against the **pane's** width: Formatted/Terminal labels collapse at 840px; Resume/Stop become 30px icon circles at 700px; path and branch leave at 520px; Find and Pin leave last. In split view, the view toggle and Resume/Stop always use their compact forms, regardless of pane width. An open Find bar starts earlier because it adds another wide control: the view toggle collapses at 900px and Find replaces the title below 760px. Every removed label retains a tooltip and explicit accessible name, so narrowing costs legibility and never function.
- **Formatted view is read-only** (rendered from the JSONL); typing happens in the **Terminal** view. The selected Formatted/Terminal surface and each Formatted reading position are session-local per conversation and survive navigation; preserve that without retaining hidden Markdown trees. Formatted is also the surface for **find-in-conversation** (`⌘F` when the main pane is focused) — and searches human and agent messages, including their code blocks. Tool sections (summaries, names, arguments, and results) are excluded whether collapsed or expanded, along with transcript chrome and hidden LaTeX source. Search never opens or expands tool content. **Closing the find bar (Esc / ✕) leaves you at the current match** — it does not snap the scroll back to where you opened search. The Formatted view also carries **jump-to-edge pills** (**Jump to top** / **Jump to bottom**) — center-aligned, **Hanken** text plus an arrow glyph, each shown **only when scrolled away from that edge** (top pill hidden at the top, bottom pill hidden at the bottom) and jumping with an **instant snap**, not a smooth scroll. They stay strictly neutral (ink / paper / gray) per the two-accent rule.
- **Transcript rendering coalesces into same-author *sections*, one header each.** `lib/messageGroups.ts#buildRenderItems` turns the lines into `RenderItem`s — prose **turns** (You / Claude / Codex text), collapsed **tool runs**, and the interrupt note — then `groupSections` bundles consecutive same-author items under a **single header** (`buildTranscript` composes both; `TranscriptView` maps `MessageBlock` over the sections, memoized on the transcript so search re-renders keep the memo). So a stretch of Claude narration + its tool activity shows **one `Claude` header**, not a header per beat. The header is a **filled tag** (a `--paper-hover` chip, Title-case Hanken at body size, `--ink-soft`) with a leading mark — the agent **logo** (`AgentLogo`, ink) or a **person** glyph for You. **Attribution is by content, not raw role:** the parser tags each `user` line `userKind` — `human` (typed prompt → "You"), `tool_result` (tool output → folded into a **tool run**, never "You"), or `interrupted` (the Esc sentinel → a centered muted note); non-conversational `user` lines (slash-command echo, `isMeta`, task-notifications) **and thinking blocks** are dropped at parse time. A single hairline rule separates a **You** (human) section from the surrounding agent section — drawn ONLY at that You↔agent boundary, never within a section (`.message.has-divider`, computed in `TranscriptView` as `dividerBefore`). **You and agent prose share one Markdown renderer** (`MarkdownBlock`), so user-authored bold, headings, lists, links, tables, inline code, and fenced code receive exactly the same styling and syntax highlighting as agent prose. The shared block rhythm keeps general top-level transitions at 22px, tightens paragraph↔paragraph and paragraph↔list boundaries to 16px, and sizes each heading tier 1px above its former token; Formatted-view links expose their URL in a wrapping compact tooltip and open through `window.api.openExternal`. **Tool activity collapses into runs:** a maximal run of consecutive `tool_use` + `tool_result` (crossing assistant-message boundaries; broken only by prose, a human turn, an interrupt, or a main↔sidechain switch) hides behind ONE disclosure — a chevron + a bold **`N tool calls`** count, a native (uncontrolled) `<details>` so the toggle is browser-instant (open-state is tracked only to word the tooltip). Expanding lists each call (**`⚙ Name`** + its input JSON) paired by id with its output (a quiet **`↳ Result`**, or red **`↳ Error`**) over the sunken block; a pending call reads *Awaiting output…*. There is **no standalone Result/Error header** — results live inside their run. A long result clamps to **6 rendered lines** with a bottom fade; only a bottom **hot-zone** (≈ the fade height) hovers/clicks (the rest of the block stays selectable / I-beam), revealing a centered **`Expand ↓` / `Collapse ↑`** + an ink scrim and toggling the clamp. An **error result keeps its red box**. Each section header carries a quiet right-aligned timestamp (`format.ts#clockTime`; full date/time on hover via `data-tip`); the tool-run header carries none. Code/mono surfaces sit at the **terminal size** (`--text-xs`). **Copy affordances** use the shared neutral `CopyButton` with a check-flash. Turn and whole-conversation copies include prose and image labels, exclude tools regardless of disclosure, and preserve complete Markdown when enabled. The footer export includes speaker attribution and unmounted content. Code/JSON/result buttons copy complete bare payloads, including clamped content; table buttons preserve the complete table in the chosen format. Selection-copy has a separate contract: outer formatting requires complete coverage plus selected non-whitespace content beyond either end, with each nested style evaluated independently. Multi-item lists preserve structural markers; tables preserve row/column structure; formulas are atomic LaTeX. Selected whitespace stays intact; spaces at generated formatting boundaries may move outside the markers to keep the Markdown valid. Non-whitespace styling is preserved, and selections never expand to recover uncertain formatting. Mixed Markdown passages escape literal punctuation consistently and may encode neighbouring characters as numeric references to keep generated delimiters valid; bare-only passages remain literal. See [architecture.md](architecture.md) for the complete copy rules. Buttons carry no searchable text and remain fixed outside horizontally scrolling payloads. Both themes and agents share this behavior.

- **Nothing highlights that a copy won't deliver.** The transcript opts into `user-select: text` against the global `body` `none`, and everything that is chrome rather than content opts back out: the speaker tag, the Sub-agent tag, the timestamp, the transcript footer, the Expand/Collapse label, *Awaiting output…*, the Interrupted note, the fenced-code language caption, decorative image glyphs, footnote return arrows, and the `⚙`/`↳` tool heads. The rule is about the PROMISE a highlight makes — a drag that sweeps up a timestamp and then omits it from the paste is a small lie. Attribution and the tool labels still reach the clipboard, but as text *generated* from the section's `data-speaker`/`data-sidechain` and the tool name (`Bash:` / `Result:`, glyphs dropped), never lifted from those elements — which is exactly why they can stay unselectable. The inverse case is fine and normal: generated structure like `**You:**` and the `---` rules was never highlighted either.
- **Every scrollbar hides at rest and reveals on scroll — horizontal ones included, at one weight.** The single-row tab strip is the explicit exception: it never shows a scrollbar and uses edge fades instead. A bar is chrome, so it earns its space only while it is being used: `.sb-autoscroll` + `--bar-thin` is the single spec for the rail, the New-conversation menu, and every scroller in the transcript, and the plain arrow (not the i-beam) belongs over all of them. Two traps this invariant is built out of, both in `global.css`: set the revealed color with `background-color`, never the `background` shorthand, which resets `background-clip` and paints the thumb over the transparent border that gives it its inset; and a block that reserves a strip for a horizontal bar must subtract `--bar-thin` from its own padding, or it reads taller and bottom-heavy next to a block that doesn't scroll. The **inline-axis counterpart is the rail's deliberately lopsided padding**: `scrollbar-gutter: stable` reserves the strip at one edge only, and the overflow clip edge sits *inside* that strip, so no descendant can paint there (a row's hover shadow cannot slide under the thumb — there is a bare gap between where it is cut and where the thumb starts). `.sb-rail-body` therefore pays `--rail-inset` on the scrollbar side and `--rail-inset + --bar-thin` on the other, which is what lands a live card's two borders the same distance from the rail's edges. **Even padding there renders visibly off-center**, so symmetric values in that one rule are the bug, not the fix. The head sits outside the scroller and so aligns to `--rail-text-inset` (the text column) instead, which is what keeps "N working · M idle" directly above the flat-row titles. Live CARDS indent a further 3px inside that column (their own border plus a wider padding), so the column is the head's and the flat rows', not a universal all-rows one.
- Design tokens live in `src/renderer/styles/tokens.css` — reuse the CSS vars; don't hardcode colors.
- **Two themes, one source of truth — a hardcoded color is a dark-mode bug, and EVERY visual change must be authored + verified in BOTH themes.** `tokens.css` defines a **neutral grayscale** light palette in `:root` and a **neutral near-black** dark palette in `:root[data-theme='dark']` (only color + shadow tokens are overridden; type/spacing/radii/motion/layout are shared). Surface tokens: `--paper-sunken` = **chrome** (the rail AND the title bar — `.sb-titlebar` uses `--paper-sunken`, not `--paper`, so they read as one continuous chrome), `--paper-pane` = **main content** (pane / Formatted / terminal), `--paper-raised` = **raised tiles** (live cards, modals, menus), `--paper` = the field/shell behind them, `--paper-code` = the **unified mono surface** for fenced + inline code AND tool result/JSON blocks (a hair off `--paper-sunken` — light `#f6f6f6`, dark `#222222` — so all mono output reads as one surface, set apart from the chrome). **Dark deliberately INVERTS the elevation** (see the dark-scope comment): the chrome (`--paper-sunken`) is *lighter* than the content canvas (`--paper-pane`), and tiles (`--paper-raised`) lighter still — the reverse of light mode and of the usual dark convention. The dark surfaces were **lightened** off pure near-black — `--paper-pane`, `--paper-sunken`, and `--paper` all sit a step up, with the **terminal background tracked to match** so the terminal doesn't read as a darker hole punched in the pane. Every surface paints from a token, so dark mode is "free" for any component that obeys this — **but "free" covers hue, not feel.** A token flips the *color* per theme; it does NOT carry perceptual *strength* across the light↔dark luminance gap, so any change with a visual dimension (shadow alpha, opacity, contrast, glow) must be **eyeballed in BOTH themes**, not just authored in one. The rail's card hover-lift shadow is the cautionary tale, with a twist: a *low-alpha* black drop shadow is **invisible** on the near-black rail (no contrast at the dark end), so the theme-aware `--shadow-sel-hover` token shares one geometry but **boosts the alpha to near-opaque in dark** — a faint black vanishes on the `--paper-sunken` rail, while an opaque one darkens toward #000 and reads (light keeps the soft low-alpha black). The cobalt **Resume** button's hover reuses the same token. "I changed a visual and only looked in light" is unfinished work. The **two-accent invariant holds in both themes**: cobalt = alive, red = destructive (both brightened for dark, soft/wash tints dark-tinted); pins/selection/metadata stay ink. **The ONE sanctioned exception to grayscale-plus-two-accents is syntax highlighting** — the Formatted view's fenced code blocks carry a full-color syntax palette (highlight.js `.hljs-*` token colors, themed per light/dark in `transcript.css`) — the **GitHub** palette (`github.css` / `github-dark.css`) ported onto our own fence surfaces (we keep `--paper-code` + `--ink`, swapping only the token hues). It carries a **per-language exception**: YAML keeps the prior muted One-Light/One-Dark palette, scoped by a `data-lang` stamp on `.md-pre-wrap` (set in `MessageBlock.tsx` from `codeLang.ts`, which folds `yml`→`yaml`) — so future per-language exceptions are a small scoped block, not new plumbing. This is the only place any hue beyond cobalt (liveness) / red (errors) appears, and it appears ONLY inside `.hljs` code — a deliberate, tightly scoped exception, not a loophole; nothing outside fenced code may introduce a third hue. (The fenced block's **language caption** — the `.md-lang` caps-label in its top-left gutter — is itself **neutral grayscale**, so it is NOT part of this exception, just an ordinary ink element sitting near the colored code.) One-off shadows use the `--shadow-color` channel (`rgba(var(--shadow-color), α)`) and overlays use `--scrim`. The Preferences modal mirrors these surfaces (chrome head+nav, content page — see the Preferences pointer in [architecture.md](architecture.md)); its **settings buttons are a light gray `--btn`, never white** — and because the elevation inverts, "lighter" is **not one shared value**: light mode's `--btn` is a hair off white, dark mode's is a readable gray, each picked per-theme rather than reused. The active theme is a JS-resolved `data-theme` on `<html>` (System/Light/Dark), **never** a bare `@media (prefers-color-scheme)` — so explicit Light/Dark beats the OS. Preferences → Appearance also exposes a **dark dock-icon toggle** (Light / Dark) that is **independent of the app theme** — it picks which dock-icon variant macOS shows, and does **not** follow (or change) the Light/Dark UI choice; the two are orthogonal settings. See the **Theming** pointer in [architecture.md](architecture.md).
- **Two agents, one experience — every change must support BOTH Claude Code and Codex, exactly as it must both themes.** Switchboard browses conversations from both agents in one unified list; a feature that only works for one is unfinished, the same way a hardcoded color is a dark-mode bug. Everything keys off `ConversationMeta.agent` (`'claude' | 'codex'`): the list, transcript, liveness dot, **resume / new**, **rename**, and the info modal all branch on it. Claude reads `~/.claude/projects/` JSONL; Codex reads `~/.codex/sessions/` rollouts (plus its `state_*.sqlite` + durable `session_index.jsonl` for titles). Resume types `claude --resume <id>` vs `codex resume <id>`; rename appends Claude's own `custom-title` line vs calls Codex's app-server `thread/name/set`; tokens render **per-agent** categories and are **never unified**. The `AGENTS` registry (`shared/types.ts`) carries each agent's label + logo, surfaced by `AgentLogo` — and **logos are ink (`currentColor`), never an accent**, so they obey the two-accent invariant and track their text. The seam is the **main-process agent split** (`sessions/{parser, codexParser, codexThreadsDb, codexSessionIndex, rename, codexRename}`, the dual-root `indexer`/`watcher`, and a per-agent boot command in `pty/manager`); the renderer consumes a **normalized** transcript/meta contract so rendering stays agent-agnostic. When you add or change anything, ask "does this hold for Codex too?" and verify both — exactly like light/dark. See the **Multi-agent (Codex)** pointer in [architecture.md](architecture.md).
