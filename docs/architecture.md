- **Contract:** `src/shared/types.ts` — IPC channel names + data types; no node/DOM imports (both sides import it). `ConversationMeta` also carries `turnState` / `turnEndedAt` / `lastActivityAt` / `awaitingTool` / `sessionKind` (the last is read verbatim from the on-disk field; `sessionKind:"bg"` is an independently resumable Claude background transcript, surfaced beside the frozen original as its own row with a dashed-ring agent mark; repeated handoffs can yield multiple rows in one lineage. Internal `daemon` / `daemon-worker` sessions are omitted, matching Claude Code's `/resume` picker); `LiveState` is the renderer's resolved working/asking/awaiting/quiet. `ConversationMeta.messageCount` is the canonical count of distinct visible human/agent prose-or-image messages — not turns, tool calls/results, thinking, or internal records; `shared/messageCount.ts` holds the shared predicate, and `MainPane` passes the metadata value to the transcript footer so every surface agrees. `IPC.sessionsRename` + `SwitchboardApi.renameConversation(sessionId, title)` are the **only** renderer→main write into a conversation (an empty title clears back to the auto-generated one). `TranscriptBlock` has **no `thinking` variant** (dropped at parse time); `TranscriptMessage` carries `userKind` (`human` / `tool_result` / `interrupted`) so the renderer attributes `user` lines without re-deriving it (see the Transcript-rendering invariant in [design.md](design.md)). The **self-update** channels (`updatesGetInfo` / `updatesCheck` / `updatesRun` / `updatesProgress` / `updatesRelaunch`) and `SwitchboardApi.getUpdateInfo` / `checkForUpdates` / `runUpdate` / `onUpdateProgress` / `relaunchForUpdate` are the renderer's window into the updater (`updatesProgress` is the one **main→renderer push**, streaming the update's log lines; the rest are invoke/handle) — see the Self-update bullet. The **dark dock-icon** (`windowSetDockIcon`), **window focus** (`windowIsFocused` for the mount-time seed + the `windowFocusChanged` push — main owns this signal outright), and **startup/refresh fade** (`appRefreshStart` / `appRefreshEnd`, both main→renderer pushes) channels round out the chrome — see their bullets below.
- **Main:** `index.ts` (window/lifecycle/smoke, + a dev-only dock icon from `build/icon.png` when unpackaged, + a dev-only window-title suffix from `SWITCHBOARD_DEV_LABEL`), `ipc.ts` (handlers; owns watcher + PtyManager — also the `windowSetDockIcon` handler that swaps the dock to `build/icon-dark.png` and the `appRefreshStart`/`appRefreshEnd` pushes that bracket the ⌘R zoom-wiggle, see their bullets), `updater.ts` + `updater-core.ts` (the self-update engine, see the Self-update bullet), `sessions/{parser,indexer,watcher,rename}.ts`, `pty/manager.ts`, `menu.ts` (custom app menu — ⌘R→Refresh, no reload roles; see the ⌘R gotcha in [gotchas.md](gotchas.md)), `windowState.ts` (persists window bounds across launches), `windowFocus.ts` (forwards the window's own focus/blur to the renderer, which cannot reliably observe its own — see the `useWindowFocus` entry under Renderer state; wired before the window is shown so the `show()`-triggered focus is forwarded rather than missed), `trafficLights.ts` (keeps the native macOS traffic lights aligned to the **page zoom** — the OS buttons don't move when ⌘+/⌘− scales the renderer, so they'd drift out of center; the renderer pings `IPC.windowSyncTrafficLights` on every `resize` (which fires on every zoom change) and main repositions via `BrowserWindow.setWindowButtonPosition`, scaled by `webContents.getZoomFactor()` — buttons stay centered + proportionally gapped to the wordmark; resting inset is nudged a hair up-and-left of macOS's centered default, and sync is **suppressed across the ⌘R refresh zoom-nudge** so the lights don't wobble with it). `sessions/rename.ts#appendCustomTitle` is the lone JSONL **write** — it appends Claude Code's own `custom-title` line (`fs.appendFile`, O_APPEND, atomic for a small line, safe alongside a live `claude`); the `IPC.sessionsRename` handler appends then **re-indexes + broadcasts `sessionsChanged` immediately** so the new title lands now rather than ~600ms later when the watcher catches the same write. The PtyManager spawns `$SHELL -l -i` then types `claude --resume <id>` / `claude --session-id <id>` (login shell = real PATH; see README "Why a login shell?"); the boot string is built by `pty/bootCommand.ts` (`bootPayloadFor`), which prefixes a **Ctrl-E/Ctrl-U line-clear** so stray prompt content (recalled history, a keystroke in the pre-boot window) can't fuse onto the command — see [gotchas.md](gotchas.md). It **gates that boot on the first renderer `resize`**, not just the shell prompt: the PTY spawns at a placeholder 80×30, so booting claude before the real terminal size arrives makes it replay the entire resume transcript at 80×30, and the real size landing mid-replay corrupts claude's cursor math into **real blank rows** in the buffer (which only a later resize/relayout clears). Gating boot on `shellReady && sized` (with a ~2.5s fallback for a terminal that's never shown) makes claude replay at the true size from its first line. PTY busy/idle (output activity, `CONFIG.busyWindowMs` = 800ms) now **only** gates the LRU cap (`CONFIG.maxLivePtys`, **default 8**, user-configurable in Preferences → Application (bounds 2–16), persisted by `useMaxLiveSessions` → pushed to the PtyManager over `IPC.ptySetMaxLive`; evicts idle sessions only, never busy work; reaching the cap raises a blocking center-top **capacity modal**, `CapWarningModal`) — it does **not** drive the liveness dot at all (a live TUI repaints constantly — every keystroke echoes as output — so PTY "busy" is ~always true). Transcript turn-state remains the primary liveness signal; the only PTY-output exception is the explicit Codex OSC notification described below.
- **Multi-agent (Codex):** Switchboard is a two-agent browser; everything keys off `ConversationMeta.agent` (`'claude' | 'codex'`), with an `AGENTS` registry (`shared/types.ts`) carrying each agent's label + logo (surfaced by `AgentLogo`, painted in `currentColor` so it stays ink, never accent). **Storage differs:** Claude writes `~/.claude/projects/<dashed-cwd>/<id>.jsonl` (cwd-bucketed; the filename stem IS the id and the `--resume` token); Codex writes `~/.codex/sessions/YYYY/MM/DD/rollout-<iso>-<uuid>.jsonl` (date-bucketed, cwd lives *inside* the file) plus a versioned `state_*.sqlite` index whose `threads.title` holds the (renamable) title. `indexer`/`watcher` scan **both roots** and merge metas **by cwd** — a repo's Claude and Codex conversations land in one group — filtering Claude `sessionKind` of `daemon` / `daemon-worker` (not `bg`), Codex non-interactive rollouts (`originator !== 'codex-tui'`), delegated Codex threads (`thread_source:"subagent"`), and archived. `codexParser.ts` preserves `thread_source` on cached metadata and `indexer.ts` applies the subagent filter afterward; do not return `null` from the parser for these rollouts, or they bypass the positive metadata cache and are reread on every live poll. **Parse:** `codexParser.ts` walks the rollout (`response_item` / `event_msg`) into the SAME normalized `TranscriptMessage` / `TranscriptBlock` shapes the Claude parser emits, so the renderer stays agent-agnostic; the human turn arrives in *either* of two `event_msg` shapes depending on the Codex version and thread kind — the per-kind `user_message` event or the newer unified `item_completed` envelope — and reading only one of them breaks preview / count / `firstActivityAt` / every human turn while leaving the title intact (see the two-human-turn-shapes gotcha in [gotchas.md](gotchas.md)); meta (preview / cwd / model / tokens / turn-state) comes from the rollout, and the displayed title is resolved by `resolveCodexTitle` (`codexSessionIndex.ts`) from `codexThreadsDb.readCodexThreads` (read-only `node:sqlite` → `threads.title` + `first_user_message`) plus `readCodexSessionNames` (the durable `session_index.jsonl`): a *distinct* `threads.title`, else the newest `session_index.jsonl` name, else the rollout-derived title — mirroring Codex's own list (see the write-≠-read gotcha in [gotchas.md](gotchas.md)). **Spawn:** `pty/agentEnv` removes inherited Claude/Anthropic runtime identity (default-deny by family, with explicit Claude config preserved) and `pty/bootCommand` builds the per-agent boot command (typed by `pty/manager`) — `claude --resume <id>` / `claude --session-id <id>` vs `codex resume <id>`; new Claude has its id at spawn, new Codex spawns **provisional** and late-binds to its rollout only on proof — `pty/codexIdentity.ts` runs `lsof` to see which Codex process holds which rollout open on which terminal device, binds only an exact one-to-one match, and emits `pty:bound`; when the evidence is missing or ambiguous the PTY stays provisional for good and the row remains behaviorally `unlinked` while sharing the hollow nothing-unread ring and italic `No messages yet` placeholder (`PtyState.provisional` crosses IPC for exactly this). See gotchas. **Rename:** `ipc.ts` `sessionsRename` dispatches by agent — Claude appends its own `custom-title` JSONL line (`rename.ts`), Codex calls the app-server `thread/name/set` over NDJSON stdio (`codexRename.ts`) — then re-indexes immediately. **New-conversation** adds an agent axis: `useAgentAvailability` (a cached login-shell `command -v claude; command -v codex` probe) + `useNewConvoDefaultAgent` (None / Claude / Codex pref) drive `NewConversationMenu`'s segmented control, which auto-collapses to a single agent when only one is installed. **Tokens** render per-agent categories and are **never unified** (Claude cache tiers vs Codex input / cached / output / reasoning + a context gauge). The **two-agent invariant** (every change must support both, the peer of the two-theme rule) lives in [design.md](design.md); the agent traps (`cleanAgentEnv`, new-Codex late-bind, rename write-≠-read, the `node:sqlite` / availability notes) are in [gotchas.md](gotchas.md). **Known limitation:** `SessionWatcher` globs only `*.jsonl`, so a Codex change touching *only* the state DB — e.g. a rename done in the Codex TUI or another process — doesn't trigger a re-index until the next jsonl write, the live poll (while a session is active), or restart (our own renames force one, so they're immediate). Watching `state_*.sqlite*` was deliberately avoided: the WAL/SHM sidecars churn on ordinary activity (and `-shm` even on reads) so it would fire constantly → frequent full reindexes, and an always-on DB poll would undo the gated live-poll design. A focus-triggered reindex is the cheap fix if this ever matters.
- **Conversation rename + info modal — two entry points, one surface (`ConversationInfoModal`).**
  - **Entry points.** The pane title is a button (`PaneHeader`, `.sb-pane-title-btn` — darkened-bg hover, no tooltip) → opens the modal in **view**; a row's **⋮ menu → Session details…** (`TallyRail`'s per-row menu, **below** read/unread) also opens it in **view**. (The `startInEdit` path remains but no entry point uses it now — both open ready to read, and the title is editable in place.) App owns `infoModal: {sessionId, edit}` and renders the modal (resolving the target's meta + pty, mirroring the rail's synth-meta fallback); while it's open App's key handler **short-circuits** (Esc closes, like Preferences / the capacity modal).
  - **Title = heading, edited in place.** An always-editable input styled as the heading (`.sb-info-title-input`): commit on **blur**, **Enter** commits *and* closes the modal, **Esc** reverts (a `suppressRef` skips the ensuing blur-commit; `stopPropagation` so App's Esc doesn't also close — first Esc backs out, second closes). Commit writes only on an actual change (never pins an auto-title). A `focusedRef`-guarded `[title]` effect re-seeds the draft from incoming title updates (a commit's re-index, or an external `/rename`) only while the user isn't editing. There's deliberately **no** "reset to auto title" affordance — it was removed; to drop a custom title, rename it.
  - **Detail sections** — caps-headed (`Section` → `.sb-info-section` + a `.label-caps` header over a `.sb-info-grid`): **Workspace** (Folder · Branch · Model) · **Activity** (Messages [visible human/agent prose-or-image messages, excluding tool plumbing] · Size · Duration) · **Tokens** (gated on having any — **Context** first [current window, a live snapshot], then the cumulative per-tier totals **Input · Output · Cache write · Cache read** by Anthropic pricing tier, all visible) · **Session** (live **Status** [the lone accent: a static cobalt dot] / **Started** first, then **Last active** · **Session ID** last).
  - **Font split.** The **data** (row labels + values) is the **terminal mono face** (`--font-mono` on `.sb-modal-info`) at **one size** (`.sb-info-value` = `--text-xs`, so e.g. Session ID and Started read identically; the `mono` Row prop now only drives truncation, not size), while the **chrome** — the editable title and the section headers (`.sb-info-section-label`) — stays in the **UI face** (Hanken, `--font-ui`/`--font-display`). A deliberate per-dialog split: the readout reads like the terminal it describes, framed by UI-font headers.
  - **Selection + copy.** Values are **selectable** (`.sb-info-value` re-enables `user-select` against the global body `none`) — highlight to copy — and **only Session ID** carries a one-click **`CopyButton`** (shared, extracted from `MessageBlock`), now the only place to copy the session ID since the right-click menu's **Copy session ID** item was removed. Timestamps (Last active / Started) show the **absolute** time only; token values are **metric-prefixed** (`format.ts#formatMetric`, e.g. `324K` / `18.4M`), and each token row's **key** (not its value) carries a plain description tooltip via `Row`'s `labelTip` (→ `data-tip` on a span hugging the label, e.g. "Base input tokens") — no raw counts surfaced.
  - **Where the values come from.** `ConversationMeta` fields computed in `extractMeta`'s existing per-line loop (negligible cost): `sizeBytes` · `model` · `firstActivityAt`, plus the token set — `inputBaseTokens` · `cacheWriteTokens` · `cacheReadTokens` · `outputTokens` (cumulative, **deduped by `message.id`** — the same response is written across multiple JSONL lines all repeating identical `usage`, so a naive sum inflates ~3×; `inputTokens` is their input subtotal) and `contextTokens` (the **last main-chain turn's** input+cache = current context-window occupancy, the snapshot Claude Code's status line shows — sidechain turns are counted in the cumulative sums but never set `contextTokens`). The 5m/1h cache-write split exists in the JSONL (`usage.cache_creation.ephemeral_*`) but is folded into `cacheWriteTokens` here.
  - **Rename flow.** `onRename` → `App.renameConversation` → `window.api.renameConversation` → the main append + immediate re-index, so the new title lands in the rail, the pane header, and the still-open modal together.
- **Liveness model — the dot is derived primarily from transcript turn-state, never generic terminal activity.**
  - **Turn-state extraction.** `sessions/parser.ts#extractTurnState` scans the transcript's main-chain tail into `ConversationMeta.turnState` + `turnEndedAt` + `lastActivityAt` + `awaitingTool`. An assistant `stop_reason` / a `turn_duration` system line ends a turn; Claude's `system` / `informational` **“Backgrounding after the current tool finishes…”** notice also ends the original transcript's turn because all continuation events move to the separate `bg` transcript. The original file has no structured turn-boundary for this handoff, so the parser necessarily matches that persisted English prefix; an upstream wording change requires updating it. A streaming fragment (no `stop_reason` yet) ⇒ in-progress; a trailing **`AskUserQuestion` / `ExitPlanMode`** tool_use ⇒ `awaiting_input` (+ `awaitingTool` — these block for the user's reply and are always a lone terminal tool_use). Sidechain lines are ignored.
  - **Non-conversational trailing `user` lines are skipped** (`classifyUserLine`): slash-command echo/output (`/model`), `!` bash I/O, background-task notifications, and `isMeta` caveats are NOT a turn. So running `/model` after a finished turn stays `awaiting`, not falsely `in_progress` — only a real typed prompt or a `tool_result` keeps a turn `in_progress`. An **interrupt sentinel** (`[Request interrupted by user]`, written when you press Esc) ends the turn ⇒ `awaiting`. The **`/compact` summary** (`isCompactSummary`) — machine-injected continuation context that *replaces* history, not a typed prompt — is likewise modeled as a finished turn ⇒ `awaiting`, so a manual `/compact` (after which Claude idles at the prompt) doesn't read as `in_progress` and breathe forever; an auto-compact's continuation assistant line that follows flips it back to `in_progress`. The summary is also dropped from the Formatted view (like the `/compact` echo beside it). *(Claude-only: Codex derives turn-state from task-lifecycle events, not the last line, so it doesn't hit this.)*
  - **Codex input notifications — the narrow runtime exception.** Structured `request_user_input` calls remain authoritative in the rollout: `codexParser.ts` reports `awaiting_input` and stamps `lastActivityAt` both when the call arrives and when its matching answer is recorded. Approval requests are not persisted there, so Switchboard-owned Codex processes receive process-local `-c` overrides enabling OSC 9 notifications only for `approval-requested` and `plan-mode-prompt` (method `osc9`, condition `always`); user configuration is never changed. The type whitelist is load-bearing because OSC 9 carries only display text: enabling all notifications would also emit assistant-response previews for `agent-turn-complete`, and a preview beginning with a recognized input prefix would be indistinguishable from a real request. `pty/codexInputNotifications.ts` recognizes only Codex's explicit `Plan mode prompt:`, `Approval requested:`, `Codex wants to edit …`, and `Approval requested by …` messages, including tmux wrapping and split chunks, while passing terminal output through untouched and bounding partial state to 4 KiB. The manager carries the detection timestamp as `PtyState.inputRequestedAt` over the existing active-PTY update. It is current only while newer than parsed rollout activity, so a matching question answer, later agent message, or turn completion supersedes it; arbitrary output and keystrokes never clear or create that runtime signal. Hooks remain a possible broader integration, but are deliberately not used: permission hooks fire before reviewer routing, so with `auto_review` they cannot distinguish an approval the reviewer will handle from one the user must handle.
  - **Four-state dot.** `resolveLiveState` (extracted to `renderer/lib/liveness.ts`, pure + unit-tested) combines transcript state plus that narrow Codex signal with a per-session **seen** marker (`useSeen`, localStorage; advanced when a conversation is selected *and* the window is focused — `useWindowFocus` — **and** on every deliberate navigation to it, which needs no focus signal at all: opening a conversation is itself attention, so read state does not rest on a single boolean): **working** (in-progress) / **asking** (blocked on your reply, unread; clears when looked at, like awaiting) / **awaiting** (finished, unread) / **quiet** (finished+seen, or live-but-not-yet-started — a session with no turn-state yet is quiet, never working).
  - **The fifth marker is NOT a liveness state.** **Two** kinds of live terminal have no transcript Switchboard can attribute to them, and `lib/rowIdentity.ts` is the single predicate for both: a provisional Codex PTY (`PtyState.provisional` — never matched to a rollout; see the Multi-agent section), and a Claude PTY carrying `PtyState.parkedJob` with nothing indexed under its id. Both are excluded from `resolveLiveState` by `lib/rowIdentity.ts#resolveRowLiveState` — the single gate-then-resolve composition that all three of App's consumers go through (the rail rows, the Live tally, the read/unread toggle), so the exclusion can no longer be omitted at one of them the way it once was — and render `.sb-dot.unlinked`, which shares the exact hollow cobalt treatment with `.sb-dot.quiet`. Liveness is read off a transcript, and an unlinked terminal has no transcript known to be its, so resolving any of the four `LiveState` values would describe someone else's conversation. Hollow means nothing linked is unread here; it is presentation reuse, not a resolved `quiet` claim. The Live tally therefore keeps its own `unlinked` bucket — calling a terminal you may be actively typing in "idle" is the misreport this exists to prevent — and pin / rename / details / mark-unread are **hidden**, not merely gated, in both the ⋮ menu and the pane header (`PaneHeader`'s `unlinked` prop drops the pin and renders the title as plain text rather than the info button): persisting anything under an id that may never name a real conversation would orphan, and a control that silently does nothing is worse than an absent one. `lib/rowIdentity.ts#displayTitleForRow` is the single title derivation for both the rail and the pane, so the header cannot name one thing while the row names another.
    They differ only in the preview slot, because they differ in *why* they are empty. An unbound Codex terminal is waiting on a first turn that normally arrives, so it reuses the ordinary italic `No messages yet` — indistinguishable from a new Claude row beside it, which is the truth of the moment. A parked-agent terminal is empty *permanently*, so it titles itself with the agent's own name and states `Terminal only — work is in a background agent`.
    `pty/claudeParkedJobs.ts` supplies `parkedJob` by watching Claude's session registry for its `parkedJobId` marker — which means only that the session **launched** an agent (it is never cleared, not on leaving Agent View nor when the agent ends), so the marker alone must never be read as a state. Pairing it with "has no indexed conversation" is what makes it usable, and re-deriving that every pass is what makes the row correct itself the moment the session writes a transcript. `sessions/claudeJobs.ts#readBgJobName` supplies the title. Full account, including the attach signal that exists but carries no job id, in the work-stream findings.
  - **Manual read/unread.** `useSeen` also holds an `unread` override map (sessionId → markedAt); `resolveLiveState`'s `manualUnread` arg forces **`awaiting`** (the solid dot) for a finished conversation — or **`asking`** (the pulse) for one blocked on your reply (`awaiting_input`), so marking a question-state unread returns it to pulsing — beating both `lookingNow` and the seen timestamp. Set it three ways: **`⇧⌘U`** (toggles the selected conversation); **Option+click** — on a live row in the left pane, or anywhere in its live terminal — which **always marks unread, never toggles**; or a row's **⋮ menu**. It **auto-expires** once a newer turn lands (`turnEndedAt > markedAt`, derived — no mutation), and is cleared by `markRead`: an explicit toggle, **selecting** the conversation (the seen-effect calls `markRead`, not just `markSeen`), or **engaging** it (a click or keystroke in the pane body, via `MainPane`'s capture-phase listener; scrolling doesn't count).
    - *Option+click wiring:* `ConversationRow`'s `onClick` branches on `e.altKey` before its live/non-live dispatch and returns without navigating; the terminal twin is a dedicated capture-phase `mousedown` listener on the `TerminalView` host (`e.altKey && e.button === 0` → `markUnread`) whose `stopPropagation` is **load-bearing** — it beats `MainPane`'s bubble-phase engage→`markRead` *and* xterm's own mouse handling, and `manualUnread` beating `lookingNow` is what makes the dot go solid even while the conversation is open+focused.
    - *⋮ row menu* (`TallyRail`, the per-row vertical 3-dot — **replaced the old right-click context menu**) offers **Pin/Unpin** and **Session details…** (on every row, live or not), the read/unread item, plus — on a live row only — **Stop session** (kills the session), and — on a not-live row only — **Resume** (spawns + focuses via `App.resumeSession`→`resume`). It opens on **click-to-toggle** *or* **right-click-at-cursor**, and is dismissed by an outside click, **Esc**, or a **rail scroll** (the scroll listener is scoped to the **rail body**, not document-wide, so scrolling the transcript doesn't close it).
  - **Timestamps.** Rows + header show `relTime(lastActivityAt ?? mtime)` (mtime is bumped by resume/metadata writes, so it isn't true last activity).
  - **Carryover demotion.** `resolveLiveState` demotes an `in_progress` turn whose `lastActivityAt` predates the live process's `PtyState.startedAt`: it belongs to a prior, now-dead run — you quit/End the app mid-turn (which writes *no* sentinel, unlike Esc), then **resume**, and the new process just replays history and idles at the prompt (without this it would breathe forever). - **Math (`lib/mathDelimiters.ts` + `MathBlock.tsx`):** both agents write math, and both use all four delimiter families — `\(…\)` / `$…$` inline and `\[…\]` / `$$…$$` display. `remark-math` reads only the dollar forms, so `normalizeMath` rewrites the LaTeX ones onto them, **length-preservingly** (each substitution is two characters for two). That property is the whole design: source offsets computed against the rewritten text index the ORIGINAL, so `rehypeSourceOffsets` and the entire copy pipeline are untouched and a formula copies back as the `\(P_i\)` the agent wrote. **Any change here must preserve length.** Detection is opt-in per block: nothing is math unless the block holds a **display block whose delimiters sit alone on their own lines**, because these delimiters overwhelmingly mean other things in coding prose (`\[DEBUG\]` is an escaped literal bracket, `sed`/`jq` are full of `\(…\)`, and `$PATH` is everywhere). Single `$` is admitted only when the block wrote its *display* math as `$$` — structural evidence of which convention the block is using, so a `\[…\]`-style block's bare `$` stays a shell sigil (see the fail-closed note in [gotchas.md](gotchas.md)). Fenced, indented, and inline code are excluded from detection as well as rewriting — by **overlap**, not containment, so a pair that starts inside a code span and ends outside it is still rejected — and a fenced ```latex sample stays visible source. Two details the offsets depend on: the rewrite buffer is built with `split('')` (UTF-16 code units) to match the offsets, never `Array.from` (code points), which one emoji before a formula would desynchronise; and display delimiters are paired in a **single pass**, since rescanning per unmatched opener is quadratic. Rendering is **KaTeX, dynamically imported** — it is the largest thing this view could pull in and math is rare, so it is not in the startup bundle; until it resolves (or forever, if it fails) each formula shows its LaTeX source, which is what the view showed before. `output: 'html'` drops KaTeX's parallel MathML tree: that halves the node count and leaves ONE text representation, where the default makes `textContent` read a formula three times over and corrupts the copy walk. **KaTeX lays glyphs out in visual, not reading, order** — a fraction emits its denominator first — so the rendered subtree carries `data-md-skip` (the existing "on screen but not source" marker) and the LaTeX rides beside it in a visually-hidden `.md-math-tex` span; the copy walk therefore collects the source and never the scrambled glyph text. Parse failures are caught and fall back to muted mono rather than KaTeX's lenient mode, which is inconsistent (it flags some failures and silently mis-renders others) and whose error styling would collide with the transcript's use of red.
- **Selection → Markdown (`lib/mdCopy.ts` + `lib/mdCopyDom.ts`):** ⌘C over a Formatted-view selection copies the underlying **Markdown source**, not the rendered text. A local `rehypeSourceOffsets` plugin in `MessageBlock` stamps every rendered element with `data-s`/`data-e` — the offsets of its markdown inside the block's source, the same `node.position` offsets the table copy button already sliced by — and every markdown override forwards them (an override destructuring only `{ children }` silently drops them, and with them that element's contribution). Descent stops at `<pre>` so rehype-highlight's token spans aren't annotated. `mdCopyDom` reads the annotated tree into a plain `SrcNode` and `mdCopy` maps rendered-text offsets to source offsets; the split keeps the hard logic DOM-free and node-testable (same reason as `theme.ts`/`themeDom.ts`). **One collector serves three callers** — the ⌘C handler, the per-turn copy button (over a range covering its own section), and both modes — which is what stops a button and a hand-drag over the same content disagreeing now that tool I/O is conditional on a run being expanded.
  Three rules govern what markup travels. **Widening is all-or-nothing**: an element's delimiters are added only when both selection ends cover it, so a partial selection never emits half a pair. **A fence inverts that** — a code block gives bare contents unless the selection reaches *outside* it, where the fence sits between the two ends in the source and must come along. A fence-only source unit therefore also carries whether the DOM range starts before or ends after it; clamped local offsets alone cannot distinguish a confined selection from one continuing into another block or message. **An orphaned delimiter is excised**, making the slice piecewise: cutting into `**bold**` and running on would otherwise carry a closing `**` that re-renders as a new run and corrupts everything downstream. Anything unprovable widens outward to the nearest enclosing element rather than guessing. Every guard is **mutation-checked**, which is how four real defects were found — including `atStart` slicing with an unclamped negative offset, silently dropping a nested run's closing delimiter.

Icon-only buttons keep an `aria-label` for the accessible name. (The only remaining `title=` in the renderer are two React *props* passing the conversation-title string, not HTML attributes.)
- **Theming (`useTheme` → `theme.ts` + `themeDom.ts`):** the app theme is `useTheme` (owned once in `App`; `localStorage` `switchboard.theme` = `system`|`light`|`dark`, default **system**). `theme.ts` is the **pure** core — `ThemeMode` / `ResolvedTheme` / `resolveTheme` — so the test suite imports it under the **node** tsconfig (which has no DOM lib); the browser-side helpers (`readThemeMode`, `systemPrefersDark`, `applyTheme`) live in `themeDom.ts` (renderer-only). Keep that split — putting a `window`/`document` reference in `theme.ts` breaks `typecheck:node`, since `test/` pulls test-imported renderer libs into the node project. `applyTheme` writes `data-theme` on `<html>` and reads the **computed** `--paper` to sync the window `backgroundColor` (drift-proof against token retunes). `main.tsx` calls `applyTheme(resolveTheme(readThemeMode(), systemPrefersDark()))` **before `root.render`** — the window is hidden until first paint, so this kills the FOUC without a CSP-blocked inline `<head>` script. `system` tracks `matchMedia('(prefers-color-scheme: dark)')` live. The resolved theme threads `App → MainPane → TerminalDeck → TerminalView` (same path as `focusReq`); `TerminalView` holds two xterm theme objects (`LIGHT_THEME` / `DARK_THEME`, a neutral 16-color ANSI palette + cobalt selection) and swaps `term.options.theme` live on change, so a running `claude` recolors in place (the construction effect captures the initial theme; a `[theme]` effect owns changes). Controls: a **sun/moon** title-bar toggle (`TitleBar`, flips light↔dark as an explicit choice) and the Preferences **Appearance** page's System/Light/Dark segmented control (reuses `.sb-seg`). Window-bg sync rides `IPC.windowSetBackgroundColor` (`shared/types` + preload `setBackgroundColor` + an `ipcMain.on` calling `BrowserWindow.fromWebContents(e.sender)?.setBackgroundColor`); `main/index.ts` seeds the initial `backgroundColor` from `nativeTheme.shouldUseDarkColors` for the hidden pre-paint frame.
- **Dark dock-icon toggle (`useDarkIcon` → `IPC.windowSetDockIcon`):** an Appearance setting that swaps the macOS **dock icon** to a dark-theme variant. `build/icon-dark.png` ships via electron-builder **`extraResources`** so it resolves in the packaged app; the renderer holds the choice in `useDarkIcon` (localStorage) and **pushes the saved value on mount** over `IPC.windowSetDockIcon`, whose handler in `ipc.ts` sets the dock image (and reverts to the default when off).
- **Startup/refresh fade (`AppVeil` + `IPC.appRefreshStart`/`appRefreshEnd`):** a white (black in dark) veil that hides relayout flashes. Main brackets the **⌘R Refresh** zoom-wiggle (and the initial launch fade) with `appRefreshStart` → `appRefreshEnd` pushes; the `AppVeil` component fades in over the start and out on the end, so the zoom-nudge relayout (and first paint) plays behind the veil rather than on screen.
