Internal `daemon` / `daemon-worker` sessions are omitted, matching Claude Code's `/resume` picker); `LiveState` is the renderer's resolved working/asking/awaiting/quiet. `ConversationMeta.messageCount` is the canonical count of distinct visible human/agent prose-or-image messages — not turns, tool calls/results, thinking, or internal records; `shared/messageCount.ts` holds the shared predicate, and `MainPane` passes the metadata value to the transcript footer so every surface agrees. `IPC.sessionsRename` + `SwitchboardApi.renameConversation(sessionId, title)` are the **only** renderer→main write into a conversation (an empty title clears back to the auto-generated one). `TranscriptBlock` has **no `thinking` variant** (dropped at parse time); `TranscriptMessage` carries `userKind` (`human` / `tool_result` / `interrupted`) so the renderer attributes `user` lines without re-deriving it (see the Transcript-rendering invariant in [design.md](design.md)). - **Main:** `index.ts` (window/lifecycle/smoke, + a dev-only dock icon from `build/icon.png` when unpackaged, + a dev-only window-title suffix from `SWITCHBOARD_DEV_LABEL`), `ipc.ts` (handlers; owns watcher + PtyManager — also the `windowSetDockIcon` handler that swaps the dock to `build/icon-dark.png` and the `appRefreshStart`/`appRefreshEnd` pushes that bracket the ⌘R zoom-wiggle, see their bullets), `updater.ts` + `updater-core.ts` (the self-update engine, see the Self-update bullet), `sessions/{parser,indexer,watcher,rename}.ts`, `pty/manager.ts`, `menu.ts` (custom app menu — ⌘R→Refresh, no reload roles; see the ⌘R gotcha in [gotchas.md](gotchas.md)), `windowState.ts` (persists window bounds across launches), `windowFocus.ts` (forwards the window's own focus/blur to the renderer, which cannot reliably observe its own — see the `useWindowFocus` entry under Renderer state; wired before the window is shown so the `show()`-triggered focus is forwarded rather than missed), `trafficLights.ts` (keeps the native macOS traffic lights aligned to the **page zoom** — the OS buttons don't move when ⌘+/⌘− scales the renderer, so they'd drift out of center; the renderer pings `IPC.windowSyncTrafficLights` on every `resize` (which fires on every zoom change) and main repositions via `BrowserWindow.setWindowButtonPosition`, scaled by `webContents.getZoomFactor()` — buttons stay centered + proportionally gapped to the wordmark; resting inset is nudged a hair up-and-left of macOS's centered default, and sync is **suppressed across the ⌘R refresh zoom-nudge** so the lights don't wobble with it). `sessions/rename.ts#appendCustomTitle` is the lone JSONL **write** — it appends Claude Code's own `custom-title` line (`fs.appendFile`, O_APPEND, atomic for a small line, safe alongside a live `claude`); the `IPC.sessionsRename` handler appends then **re-indexes + broadcasts `sessionsChanged` immediately** so the new title lands now rather than ~600ms later when the watcher catches the same write. The PtyManager spawns `$SHELL -l -i` then types `claude --resume <id>` / `claude --session-id <id>` (login shell = real PATH; see README "Why a login shell?"); the boot string is built by `pty/bootCommand.ts` (`bootPayloadFor`), which prefixes a **Ctrl-E/Ctrl-U line-clear** so stray prompt content (recalled history, a keystroke in the pre-boot window) can't fuse onto the command — see [gotchas.md](gotchas.md). It **gates that boot on the first renderer `resize`**, not just the shell prompt: the PTY spawns at a placeholder 80×30, so booting claude before the real terminal size arrives makes it replay the entire resume transcript at 80×30, and the real size landing mid-replay corrupts claude's cursor math into **real blank rows** in the buffer (which only a later resize/relayout clears). Gating boot on `shellReady && sized` (with a ~2.5s fallback for a terminal that's never shown) makes claude replay at the true size from its first line. PTY busy/idle (output activity, `CONFIG.busyWindowMs` = 800ms) is now only a coarse status reported to the renderer as a **fallback** for the liveness dot, and drives no decision: terminal output cannot separate a working agent from a resting one, because an agent TUI may repaint on a fixed timer whether or not anything is happening — which leaves such a PTY permanently "busy". Transcript turn-state is the primary liveness signal; the only PTY-output exception is the explicit Codex OSC notification described below. **The LRU cap** (`CONFIG.maxLivePtys`, **default 8**, user-configurable in Preferences → Application (bounds 2–16), persisted by `useMaxLiveSessions` → pushed to the PtyManager over `IPC.ptySetMaxLive`) therefore reads turn-state and real use instead — the decision is pure and mutation-checked in `pty/evictionPolicy.ts#chooseEvictionTargets`. It consumes a **resolved** activity, never the raw `turnState`: `shared/turnActivity.ts#resolveTurnActivity` is the one derivation the liveness dot also uses, because `turnState` is wrong in two opposite directions — it reads `in_progress` on a turn a previous process abandoned (so every resumed interrupted session would be protected forever) and `awaiting` while a terminal holds a question the agent never wrote down (so a real unanswered prompt would be discarded). That resolution takes a **third** input beyond the transcript and the runtime notification: `[Claude] PtySession.registryStatus`, Claude's own `busy`/`idle` for the session, read from its live-session registry by `pty/claudeParkedJobs.ts` (the same file, watch and pass as the parked-agent marker, parsed separately because a record can carry either claim without the other). It is the only first-party activity signal either agent publishes and the only one that catches work the transcript cannot — Anthropic documents that a subagent **runs inside the parent session's process**, so stopping that terminal destroys it, while the parent may write no transcript line for the subagent's whole duration. It ranks just below `asking` (a session blocked on the user is not working, whatever it reports) and above the unknown gate (so a busy terminal with no attributable transcript reads as working, not empty). Codex publishes no equivalent, so this is a Claude-side refinement, like rename; null means "no claim" and falls back to the transcript, so losing the registry costs the refinement and nothing else. **Only three things are protected outright** — `working` (now including that registry-reported work), `asking`, and a terminal on screen — because each destroys something that exists nowhere else, and because any rule that protects a terminal *forever* is a way to exceed the cap without limit. Everything else is ORDER, ranked by what would be lost: an empty terminal, then an idle conversation, then a terminal with no attributable transcript that has been used (a composed-but-unsent message, or a shell the agent exited to), least-recently-used first within a tier. **Two time bounds sit alongside the tiers, and both exist so that no protection is permanent.** `RECENT_USE_GRACE_MS` protects any *used* session briefly, because `activity` comes from the index and a turn just submitted still reads as finished until the next pass; it is gated on real use, since an untouched terminal holds nothing however recently it was opened. `STALE_REQUEST_MS` bounds the `asking` veto, which is the one veto with no natural end: a question the agent answers is superseded by later transcript activity and one the user answers is cleared by `markUsed` (a person typing IS the response), but a question merely **declined** leaves neither trace, so the prompt would claim the terminal for as long as it lived. Lapsing only removes the veto — the terminal is then ranked as the finished turn its transcript shows, and the liveness dot deliberately keeps pulsing, because the prompt really is still on screen. **Do not add a longer grace for an unattributable terminal.** It would be reaching for the gap between submitting a first turn and its conversation becoming attributable, which the recency guard already covers for every activity — while what it would actually catch is a terminal merely *typed into* and never submitted, a state that never resolves, so a half-written line would hold a slot for as long as the user kept touching it. What protects a possible draft is its rank, not a timer. `enforceCap` runs at spawn and takes **as many as it takes**, since the set can legitimately sit above the cap — lowering the cap in Preferences deliberately closes nothing by itself, so one eviction per spawn would never converge. Its two non-transcript inputs are reported by the renderer, not inferred: real use over `IPC.ptyUsed` (from the keyboard/paste/drop handlers — see the `onData` gotcha in [gotchas.md](gotchas.md) for why written bytes cannot be used), and on-screen terminals over `IPC.ptyVisible` (unioned across windows, since only a renderer knows which tab is active in which pane).
- **Multi-agent (Codex):** Switchboard is a two-agent browser; everything keys off `ConversationMeta.agent` (`'claude' | 'codex'`), with an `AGENTS` registry (`shared/types.ts`) carrying each agent's label + logo (surfaced by `AgentLogo`, painted in `currentColor` so it stays ink, never accent). **Storage differs:** Claude writes `~/.claude/projects/<dashed-cwd>/<id>.jsonl` (cwd-bucketed; the filename stem IS the id and the `--resume` token); Codex writes `~/.codex/sessions/YYYY/MM/DD/rollout-<iso>-<uuid>.jsonl` (date-bucketed, cwd lives *inside* the file) plus a versioned `state_*.sqlite` index whose `threads.title` holds the (renamable) title. `indexer`/`watcher` scan **both roots** and merge metas **by cwd** — a repo's Claude and Codex conversations land in one group — filtering Claude `sessionKind` of `daemon` / `daemon-worker` (not `bg`), Codex non-interactive rollouts (`originator !== 'codex-tui'`), delegated Codex threads (`thread_source:"subagent"` / `"guardian_review"` or a structured `source.subagent` marker), and archived. `codexParser.ts` preserves `thread_source` and derives `codexSubagent` on cached metadata; `indexer.ts` applies the subagent filter afterward; do not return `null` from the parser for these rollouts, or they bypass the positive metadata cache and are reread on every live poll. **Parse:** `codexParser.ts` walks the rollout (`response_item` / `event_msg`) into the SAME normalized `TranscriptMessage` / `TranscriptBlock` shapes the Claude parser emits, so the renderer stays agent-agnostic; the human turn arrives in *either* of two `event_msg` shapes depending on the Codex version and thread kind — the per-kind `user_message` event or the newer unified `item_completed` envelope — and reading only one of them breaks preview / count / `firstActivityAt` / every human turn while leaving the title intact (see the two-human-turn-shapes gotcha in [gotchas.md](gotchas.md)); meta (preview / cwd / model / tokens / turn-state) comes from the rollout, and the displayed title is resolved by `resolveCodexTitle` (`codexSessionIndex.ts`) from `codexThreadsDb.readCodexThreads` (read-only `node:sqlite` → `threads.title` + `first_user_message`) plus `readCodexSessionNames` (the durable `session_index.jsonl`): a *distinct* `threads.title`, else the newest `session_index.jsonl` name, else a cleaned database auto-title, else the rollout-derived title. Comparisons use the complete trimmed strings before cleaning; auto-titles receive first-line cleanup and the existing 80-character cap, while explicit Codex names retain their wording. This preserves Codex's rename precedence (see the write-≠-read gotcha in [gotchas.md](gotchas.md)). **Spawn:** `pty/agentEnv` removes inherited Claude/Anthropic runtime identity (default-deny by family, with explicit Claude config preserved) and `pty/bootCommand` builds the per-agent boot command (typed by `pty/manager`) — `claude --resume <id>` / `claude --session-id <id>` vs `codex resume <id>`; new Claude has its id at spawn, new Codex spawns **provisional** and late-binds to its rollout only on proof — `pty/codexIdentity.ts` runs `lsof` to see which Codex process holds which rollout open on which terminal device, binds only an exact one-to-one match, and emits `pty:bound`; while the evidence is missing or ambiguous the PTY stays provisional and the row remains behaviorally `unlinked` while sharing the hollow nothing-unread ring and italic `No messages yet` placeholder (`PtyState.provisional` crosses IPC for exactly this). Identity is **maintained, not merely established** — every live Codex PTY stays a probe target, including a *resumed* one whose id came from a click and was never observed — so a terminal that has moved on to another conversation is corrected through the same `pty:bound` path instead of naming the old one forever; `Live.identityConfirmed` records that the OS has actually seen a terminal, which is what lets probing go quiet once they all have. `pty:bound` carries a **`PtyBindKind`** (`'initial' | 'correction'`) because the renderer must handle the two oppositely, and the dividing line is **conversation-owned vs terminal-owned state**: persisted seen/unread markers and **earlier** history stops belong to the id, so a correction leaves them where they are (both ids are durable conversations — moving the markers deletes one's read state and overwrites the other's, and rewriting earlier stops retargets genuine past visits), while the current selection, the **current** history stop, the surface that selection is showing, and the row's Live slot describe the terminal and follow it — the selection, stop and surface only when the user is actually on that terminal. An initial bind has no conversation-owned state to protect (the placeholder names nothing and is ceasing to exist), so everything migrates. The decision is pure and mutation-checked in `lib/bindPolicy.ts#bindActions`; the effect in `App` is only wiring, and renderer migrations update `useSeen.rekey`, `viewBySession`, tabs and `useLiveOrder.retarget`, while main rekeys the shared history on initial bind and retargets its current visit only when a focused correction's bound-tab claim commits. `bindCodex` emits `bound` **before** `active-changed` so the Live slot is retargeted before the new id reaches the order sync. Verification rides the re-index, so it is best-effort: an idle terminal is not re-probed until output or a watcher event resumes it. See gotchas. **Rename:** `ipc.ts` `sessionsRename` dispatches by agent — Claude appends its own `custom-title` JSONL line (`rename.ts`), Codex calls the app-server `thread/name/set` over NDJSON stdio (`codexRename.ts`) — then re-indexes immediately. **New-conversation** adds an agent axis: `useAgentAvailability` (a cached login-shell `command -v claude; command -v codex` probe) + `useNewConvoDefaultAgent` (None / Claude / Codex pref) drive `NewConversationMenu`'s segmented control, which auto-collapses to a single agent when only one is installed. **Tokens** render per-agent categories and are **never unified** (Claude cache tiers vs Codex input / cached / output / reasoning + a context gauge). The **two-agent invariant** (every change must support both, the peer of the two-theme rule) lives in [design.md](design.md); the agent traps (`cleanAgentEnv`, new-Codex late-bind, rename write-≠-read, the `node:sqlite` / availability notes) are in [gotchas.md](gotchas.md). **Known limitation:** `SessionWatcher` globs only `*.jsonl`, so a Codex change touching *only* the state DB — e.g. a rename done in the Codex TUI or another process — doesn't trigger a re-index until the next jsonl write, the live poll (while a session is active), or restart (our own renames force one, so they're immediate). Watching `state_*.sqlite*` was deliberately avoided: the WAL/SHM sidecars churn on ordinary activity (and `-shm` even on reads) so it would fire constantly → frequent full reindexes, and an always-on DB poll would undo the gated live-poll design. A focus-triggered reindex is the cheap fix if this ever matters.
- **Session visibility:** `ConversationIndexSnapshot` carries visible `groups` and `hiddenSessionIds` together through the list/change IPC channels. Main retains recognized hidden ids for the process lifetime, filters stale conversation requests and tab transfers, and excludes them from terminal-binding candidates. Renderer subscription ordering lives in `snapshotSync.ts`: subscribe before the initial query, and a pushed snapshot wins over a delayed initial response. `usePaneLayout` removes hidden tabs through the bulk-close reducer before presentation and commits the cleaned layout before further interactions. Active and dormant workspace layouts reject hidden ids, including stale writes; restoration acknowledgement keys use the same filtering. Satellite creation awaits initial indexing before consuming the current filtered dormant layouts. A workspace clear during the wait takes effect; a failed index, closed requester, or disposed IPC layer leaves those layouts unconsumed. Repeated valid activation requests consume them once. History playback skips hidden visits without deleting other stops, and automatic tab cleanup does not record a visit. Unknown or temporarily unavailable sessions are retained. Running PTYs remain mounted and counted for capacity; hidden sessions do not appear in the rail or its live tally.
- **Conversation rename + info modal — two entry points, one surface (`ConversationInfoModal`).**
  - **Entry points.** The pane title is a button (`PaneHeader`, `.sb-pane-title-btn` — darkened-bg hover, no tooltip) → opens the modal in **view**; a row's **⋮ menu → Session details…** (`TallyRail`'s per-row menu, **below** read/unread) also opens it in **view**. (The `startInEdit` path remains but no entry point uses it now — both open ready to read, and the title is editable in place.) App owns `infoModal: {sessionId, edit}` and renders the modal (resolving the target's meta + pty, mirroring the rail's synth-meta fallback); while it's open App's key handler **short-circuits** (Esc closes, like Preferences).
  - **Title = heading, edited in place.** An always-editable input styled as the heading (`.sb-info-title-input`): commit on **blur**, **Enter** commits *and* closes the modal, **Esc** reverts (a `suppressRef` skips the ensuing blur-commit; `stopPropagation` so App's Esc doesn't also close — first Esc backs out, second closes). Commit writes only on an actual change (never pins an auto-title). A `focusedRef`-guarded `[title]` effect re-seeds the draft from incoming title updates (a commit's re-index, or an external `/rename`) only while the user isn't editing. There's deliberately **no** "reset to auto title" affordance — it was removed; to drop a custom title, rename it.
  - **Detail sections** — caps-headed (`Section` → `.sb-info-section` + a `.label-caps` header over a `.sb-info-grid`): **Workspace** (Folder · Branch · Model) · **Activity** (Messages [visible human/agent prose-or-image messages, excluding tool plumbing] · Size · Duration) · **Tokens** (gated on having any — **Context** first [current window, a live snapshot], then the cumulative per-tier totals **Input · Output · Cache write · Cache read** by Anthropic pricing tier, all visible) · **Session** (live **Status** [the lone accent: a static cobalt dot] / **Started** first, then **Last active** · **Session ID** last).
  - **Font split.** The **data** (row labels + values) is the **terminal mono face** (`--font-mono` on `.sb-modal-info`) at **one size** (`.sb-info-value` = `--text-xs`, so e.g. Session ID and Started read identically; the `mono` Row prop now only drives truncation, not size), while the **chrome** — the editable title and the section headers (`.sb-info-section-label`) — stays in the **UI face** (Hanken, `--font-ui`/`--font-display`). A deliberate per-dialog split: the readout reads like the terminal it describes, framed by UI-font headers.
  - **Selection + copy.** Values are **selectable** (`.sb-info-value` re-enables `user-select` against the global body `none`) — highlight to copy — and **only Session ID** carries a one-click **`CopyButton`** (shared, extracted from `MessageBlock`), now the only place to copy the session ID since the right-click menu's **Copy session ID** item was removed. Timestamps (Last active / Started) show the **absolute** time only; token values are **metric-prefixed** (`format.ts#formatMetric`, e.g. `324K` / `18.4M`), and each token row's **key** (not its value) carries a plain description tooltip via `Row`'s `labelTip` (→ `data-tip` on a span hugging the label, e.g. "Base input tokens") — no raw counts surfaced.
  - **Where the values come from.** `ConversationMeta` fields computed in `extractMeta`'s existing per-line loop (negligible cost): `sizeBytes` · `model` · `firstActivityAt`, plus the token set — `inputBaseTokens` · `cacheWriteTokens` · `cacheReadTokens` · `outputTokens` (cumulative, **deduped by `message.id`** — the same response is written across multiple JSONL lines all repeating identical `usage`, so a naive sum inflates ~3×; `inputTokens` is their input subtotal) and `contextTokens` (the **last main-chain turn's** input+cache = current context-window occupancy, the snapshot Claude Code's status line shows — sidechain turns are counted in the cumulative sums but never set `contextTokens`). The 5m/1h cache-write split exists in the JSONL (`usage.cache_creation.ephemeral_*`) but is folded into `cacheWriteTokens` here.
  - **Rename flow.** `onRename` → `App.renameConversation` → `window.api.renameConversation` → the main append + immediate re-index, so the new title lands in the rail, the pane header, and the still-open modal together.
- **Transcript loading and recovery:** `TranscriptLoader` caches resolved session paths and coalesces in-flight parses by session/revision. Both full-file parsers skip malformed records but propagate file-read errors. A failed cached path is evicted and resolved again with at most one retry in that request; failed fresh paths return `null` without being retained. Successful requests do no extra filesystem checks, and a late failure from an older revision cannot evict a newer resolved path.
- **Tabs, panes and windows — one model, one preference, one hard rule.**
  - **The rule: a conversation holds exactly ONE tab across the whole app.** Not one per pane, not one per window. It is what makes "the tab for this conversation" a well-defined thing — with two, the app has to nominate one for ⌘W, for the liveness dot, and for where a reveal lands, and any answer is wrong somewhere. Within a window the reducer enforces it; across windows only main can, because a renderer sees its own panes and nothing else.
  - **`lib/paneModel.ts` is the pure core.** One window holds one or two panes; each pane holds ordered `Tab`s and an `activeIndex`. The **selection is derived, never stored twice**: it is the active tab of the focused pane (`activeTabId`). `activeIndex === -1` is legal *with tabs present* — that is the welcome screen, reached from the wordmark. A tab is **preview** (the one the next ordinary open replaces, italic) or **persistent**; at most one preview per pane. The reducer never mints an id — `split` is handed its new pane's id — because a reducer reaching for a random source cannot be replayed in a test. Pane ids are unique for the window's life, not merely among live panes: terminal ownership is keyed by pane id, so reuse after an unsplit would hand a new pane the previous occupant's terminals.
  - **Open = reveal or place.** `open` resolves the conversation anywhere in the layout first. `land` handles ordinary local navigation; remote reveals and Back/Forward use main's tagged activation path, so they never create a local duplicate of a remotely owned tab. Named a pane (Split Right, Open to the Side, a drop) ⇒ **placement**, so the tab MOVES there — delegated to `move`, which already resolves everything relocation implies. No pane named (a rail click, a resume, ⌘1–9) ⇒ **reveal**, so the existing tab is activated where it is. Relocating someone's layout is not what asking to see a conversation asked for. `rekey` and `retarget` check for a name collision across the WHOLE layout for the same reason — a per-pane check let a placeholder rename itself onto an id the other pane already held.
  - **Bulk actions are single actions.** `closeMany` / `moveMany` take session ids, because a caller looping single-tab actions resolves every index against the layout it can see, and that stops being true once the first lands. Only the reducer sees the states between.
  - **Multi-selection (`lib/tabSelection.ts`)** is deliberately *outside* the layout: it is about what the user picked out, not what exists. A selection lives in ONE pane (every group action has a direction; a selection spanning both makes each ambiguous), **empty means "no multi-selection"** rather than "nothing selected" (there is always an active tab, and a one-element selection would be a second copy of that fact that could disagree), and the ⇧-anchor is a **session id, not an index**, because tabs can be dragged while a selection exists. `actionTargets` resolves controls invoked on a particular tab. Keyboard close instead uses `keyboardCloseTargets`: a group in the focused pane wins even if its active tab was deselected; without a group it closes the active tab. A singleton retained as a range anchor is not a group. `pruneSelection` runs after every layout change so no call site can forget. A plain press outside the group clears it, as does the window losing focus; ⌘/⇧ presses and actions inside the group keep it. Blank native draggable title-bar chrome is the deliberate exception because Electron suppresses its renderer pointer events.
  - **Terminals are homed, not moved (`lib/ptyHome.ts`).** One xterm per terminal per renderer, so each pane owns a disjoint set and the mapping is **sticky** — a terminal stays where it is unless its tab moves or its pane vanishes. `nextPtyHomes` returns the previous map by identity when nothing changed; it is resolved during render rather than in an effect, because an effect leaves a just-spawned terminal homeless for a committed frame and the pane then reports it as being somewhere else.
  - **A pane move REPARENTS the live xterm; it does not rebuild it.** `TerminalDeck` is mounted ONCE per window, outside `.sb-panes`, and each `TerminalView` is portalled into its pane's host — so a tab crossing panes changes only the `mountNode` prop while `key={ptyId}` holds, and React never unmounts the terminal. This is what makes the intra-window case correct *by construction* rather than by getting a snapshot right: no serialization, no replay, no lost scrollback, nothing to get wrong. `mountNode` therefore belongs in the dependency list of anything that must re-run when the host changes — notably the unpause/refit effect, since detaching an element is another way xterm's observer sees it stop intersecting while `visible` stays true, and a terminal that misses that sits frozen on its last frame in its new pane.
  - **Pane focus follows the physical DOM, including portals.** React portal events bubble through `TerminalDeck`, not the `MainPane` whose DOM host contains the xterm, so each pane installs one native capture-phase `pointerdown` listener on its root. Pointer events are essential here: modifier selection prevents the default pointer action and therefore suppresses the compatibility `mousedown`. Clicking an unfocused terminal therefore changes `focusIndex` before xterm takes the keyboard; pane styling, ⌘W, ⌘F and tab shortcuts cannot continue targeting its sibling.
  - **Crossing WINDOWS is the one case that serializes** (`@xterm/addon-serialize`, bounded by `HANDOFF_SCROLLBACK_ROWS`). A second renderer cannot share the first's xterm, so ownership transfer captures a snapshot, stages it at the destination, and only then commits the owner — ordered, not transactional: `stage` reports that the destination accepted the bytes, not that it rebuilt from them. The snapshot carries buffers, cursor and a subset of public modes, **not full parser state** — DECSTBM scroll margins and the DECSC saved cursor do not survive, which `test/ptySnapshot.test.ts` pins as named limitations rather than leaving uncovered. `PtyManager.repaint()` closes most of that gap by stepping one column out and back so the foreground process takes a SIGWINCH at unchanged geometry; a full-screen agent TUI answers by reissuing its own margins and redrawing. `ptyStream` keeps only output xterm has not acknowledged, so nothing is replayed twice.
  - **History depth is ONE decision in `shared/terminalHistory.ts`.** `CODEX_REPLAY_ROWS` (passed to Codex as `tui.terminal_resize_reflow_max_rows`) and `HANDOFF_SCROLLBACK_ROWS` are deliberately equal and move together. They are not interchangeable: Codex writes history to the normal buffer and, on *every* resize, clears its scrollback and re-inserts the newest rows from its own transcript — so for Codex the first constant is what you can scroll back to, including right after a handoff, whose repaint nudge is itself a resize. Claude runs on the alternate screen (no scrollback) while its agent lives, so the second constant only matters once that agent exits to a plain shell, where nothing rebuilds anything. Left unset, Codex resolves the cap from its own terminal detection and falls back to 1,000 rows for a host it does not recognise (ours), so it is set explicitly to pin the depth rather than inherit one that can change. Both are smaller than the live xterm `scrollback`, which is sized for ordinary shell output.
  - **Tab layout survives a restart** (`shared/tabWorkspace.ts` + `main/tabWorkspaceStore.ts`). Versioned JSON in userData holds each window's pane membership, order and active tab — never terminals, preview flags, view mode, find state or scroll position, so a restore reopens Formatted views and restarts no agents. Writes are coalesced, then replaced through a same-directory temporary file + atomic rename; quit flushes synchronously. The sanitizer bounds panes at 2, bounds windows at `MAX_RESTORED_WINDOWS`, and de-duplicates ids across windows; when two live window snapshots briefly overlap during a move, main's `tabOwner` wins if its window has persisted that tab, otherwise first occurrence remains the loss-avoiding fallback. Only the primary saved window is created at launch; satellites stay dormant until the renderer confirms the feature is active. If the feature starts off, enabling it restores the primary before any layout write and then opens the satellites. A restored id missing from one lossy filesystem index is retained as a no-history tab until it reappears or the user closes it. **Clearing is keyed to switching the feature OFF, never to merely being off** — `ignore` is distinct from `clear`, because persisting the off-path's single preview would be equally destructive.
  - **Dragging.** `lib/dropTarget.ts` is the pure geometry — it picks a row from y then a gap from x, supporting wrapped rows and the single horizontal row alike, and resolves a pointer outside every band to the nearest. Caret placement translates viewport rectangles through both scroll offsets. In horizontal mode, `useTabReorder` scrolls while the pointer rests inside either edge, retains subpixel movement between frames, and re-evaluates the destination as the strip scrolls; release and cancellation stop the animation. `useTabReorder` captures the pressed tab immediately, preserving ordinary clicks, then transfers capture to the strip at the drag threshold. Release, cancellation, Escape and genuine capture loss clean up the gesture; a new press clears any click suppression left by an escaped outside release. It keeps every carried source tab invisibly in flow so no neighbour moves, excludes all their indices when computing the reducer destination, and always hit-tests the release point. The caret is always visible, including the left edge of the origin; dropping a group there is a true no-op even for a scattered selection. A paint-only leading rule restores the edge after a hidden run only when its follower is on the same row. The moving visual is one fixed transparent shell: the real clone over one or two exact pseudo-card layers (two cards for 2, three for 3+), so dark surfaces and rounded-corner spacing stay uniform at constant per-frame cost. **Cross-window** drag is refereed by main: while a button is held the OS delivers moves only to the originating window, so main reads the cursor on demand between `tabDragBegin` and drop. Deliberately not generalised with the rail's single-column reorder.
  - **Cross-window tab ownership is reported, while placement is reserved.** Each renderer reports its complete tab set; main's `tabOwner` is authoritative. Explicit placement claims are marked pending so an older target report cannot erase them before adoption; the first report containing the id confirms the claim. Codex corrections use a reservation/commit handshake: main validates the PTY owner and identity without moving the tab, the renderer retargets, then a layout effect commits ownership only after the corrected tab is selected. Initial binds retire the placeholder claim and send an adoption token only to its former tab owner, independently of PTY ownership. The real tab's existing owner remains untouched until the reducer removes the placeholder and retains the real tab; a missing placeholder cancels the token. A per-PTY renderer map allows several inactive initial binds to commit together. Reservations are single-use and are discarded on superseding binds, PTY exit, or window closure.
  - **Shared state across windows.** Every window shares one `localStorage`, and none owns it. `useSeen` and `usePins` apply each change to what is **on disk** — re-read, fold in one change, write back — rather than serialising their in-memory copy. Preference hooks subscribe before immediately re-reading, closing the render-to-effect gap; storage events update state only, while explicit user setters alone write, so synchronisation cannot echo a stale mount value back. Pure merge/order rules return their input by identity when nothing changed, skipping both writes and renders.
  - **The FEATURE FLAG gates actions, not the model.** OFF is a degenerate case of the same shape — one pane, one always-preview tab — so `useTabsEnabled` gates only the strip's presence, the promotion gestures, and the split/window commands. Nothing below asks about it. Called a *feature flag* in developer docs because that is what it is — a seam that can be switched off and eventually removed; it surfaces to users as **Preferences → Beta Features → Tabs and split view**, which is where the README and the setting's own copy name it. Beta Features is its **own page** in the Preferences nav, between Application and Shortcuts, so nothing outside it inherits the caveat.
  - **The preference is stored only when the user chooses it** (`lib/tabsPreference.ts`). It defaults **off**, and an ABSENT stored value means "never chose" rather than "chose off" — so `DEFAULT_TABS_ENABLED` can later be flipped on and will reach everyone who has not opted out, while an explicit `false` is respected. Writing from an effect keyed on the current value would fire on mount too, stamping an explicit `false` into every profile that merely opened the app and quietly stranding that flip. `parseTabsEnabled` takes its fallback as a **parameter** for the same reason: while the default is `false`, "absence follows the default" and "always returns false" are indistinguishable, so the rule is only assertable at a default of `true`.
  - **Tab presentation** (`useTabLayout` + `tabLayoutPreference`): `switchboard.tabLayout` stores `wrap` (default) or `scroll`, separately from enablement and workspace contents. Preferences → Beta Features → Tab layout stays visible but disabled while tabs are off, with its heading and control dimmed and its explanation readable; the choice survives toggling the parent setting. Explicit setters alone write; `useStorageSync` propagates the choice across windows. `useTabStripScroll` handles overflow, wheel scrolling, active-tab reveal, shared-divider sizing, and layout/font resizing without React state updates on scroll. Wrap grows to fit all rows. Neither layout reserves a native scrollbar lane; horizontal mode uses a fixed wrapper to fade hidden edges. Every tab permanently reserves a 10px liveness/close slot after a 6px title gap, with 8px right padding; the 17px close target stays centered on the slot, so dot changes affect no geometry. Horizontal rules belong to one absolute `.sb-tab-rules` layer above every tab fill, with a native 1px border at each distinct row bottom. `tabRuleGeometry` reads precise rectangles for the viewport and tabs; rounded client dimensions lose fractional edge coverage at zoom. It derives row positions and content extents without reading the decoration’s prior scroll extent, so closing tabs shrinks the layer. `test/tabLayoutPreference.test.ts` and `test/tabScroll.test.ts` cover preference parsing, divider geometry, fade boundaries, wheel units, and drag-edge speeds. `npm run test:tabs-ui` runs the real component and hook under Electron, including native zoom steps, border pixel coverage, resizing, tab closure, and layout transitions. Drag-scroll motion tracks its target strip, direction, and rounding remainder together. It tolerates rounded scroll endpoints, discards clamped movement, and restarts without a backlog when direction or target changes.
- **Liveness model — the dot is derived primarily from transcript turn-state, never generic terminal activity.**
  - **Turn-state extraction.** `sessions/parser.ts#extractTurnState` scans the transcript's main-chain tail into `ConversationMeta.turnState` + `turnEndedAt` + `lastActivityAt` + `awaitingTool`. An assistant `stop_reason` / a `turn_duration` system line ends a turn; Claude's `system` / `informational` **“Backgrounding after the current tool finishes…”** notice also ends the original transcript's turn because all continuation events move to the separate `bg` transcript. The original file has no structured turn-boundary for this handoff, so the parser necessarily matches that persisted English prefix; an upstream wording change requires updating it. A streaming fragment (no `stop_reason` yet) ⇒ in-progress; a trailing **`AskUserQuestion` / `ExitPlanMode`** tool_use ⇒ `awaiting_input` (+ `awaitingTool` — these block for the user's reply and are always a lone terminal tool_use). Sidechain lines are ignored.
  - **Non-conversational trailing `user` lines are skipped** (`classifyUserLine`): slash-command echo/output (`/model`), `!` bash I/O, background-task notifications, and `isMeta` caveats are NOT a turn. So running `/model` after a finished turn stays `awaiting`, not falsely `in_progress` — only a real typed prompt or a `tool_result` keeps a turn `in_progress`. An **interrupt sentinel** (`[Request interrupted by user]`, written when you press Esc) ends the turn ⇒ `awaiting`. The **`/compact` summary** (`isCompactSummary`) — machine-injected continuation context that *replaces* history, not a typed prompt — is likewise modeled as a finished turn ⇒ `awaiting`, so a manual `/compact` (after which Claude idles at the prompt) doesn't read as `in_progress` and breathe forever; an auto-compact's continuation assistant line that follows flips it back to `in_progress`. The summary is also dropped from the Formatted view (like the `/compact` echo beside it). *(Claude-only: Codex derives turn-state from task-lifecycle events, not the last line, so it doesn't hit this.)*
  - **Codex input notifications — the narrow runtime exception.** Structured `request_user_input` calls remain authoritative in the rollout: `codexParser.ts` reports `awaiting_input` and stamps `lastActivityAt` both when the call arrives and when its matching answer is recorded. Approval requests are not persisted there, so Switchboard-owned Codex processes receive process-local `-c` overrides enabling OSC 9 notifications only for `approval-requested` and `plan-mode-prompt` (method `osc9`, condition `always`); user configuration is never changed. The type whitelist is load-bearing because OSC 9 carries only display text: enabling all notifications would also emit assistant-response previews for `agent-turn-complete`, and a preview beginning with a recognized input prefix would be indistinguishable from a real request. `pty/codexInputNotifications.ts` recognizes only Codex's explicit `Plan mode prompt:`, `Approval requested:`, `Codex wants to edit …`, and `Approval requested by …` messages, including tmux wrapping and split chunks, while passing terminal output through untouched and bounding partial state to 4 KiB. The manager carries the detection timestamp as `PtyState.inputRequestedAt` over the existing active-PTY update. It is current only while newer than parsed rollout activity, so a matching question answer, later agent message, or turn completion supersedes it; arbitrary output and keystrokes never clear or create that runtime signal. Hooks remain a possible broader integration, but are deliberately not used: permission hooks fire before reviewer routing, so with `auto_review` they cannot distinguish an approval the reviewer will handle from one the user must handle.
  - **Four-state dot.** `resolveLiveState` (extracted to `renderer/lib/liveness.ts`, pure + unit-tested) combines transcript state plus that narrow Codex signal with a per-session **seen** marker (`useSeen`, localStorage; advanced when a conversation is selected *and* the window is focused — `useWindowFocus` — **and** on every deliberate navigation to it, which needs no focus signal at all: opening a conversation is itself attention, so read state does not rest on a single boolean): **working** (in-progress) / **asking** (blocked on your reply, unread; clears when looked at, like awaiting) / **awaiting** (finished, unread) / **quiet** (finished+seen, or live-but-not-yet-started — a session with no turn-state yet is quiet, never working).
    - **`[Claude]` A quiet dot is upgraded to working when Claude reports itself busy** (`PtyState.registryStatus`, see the LRU-cap bullet under Main). This is the case where a subagent is running inside the session's process and the parent has written no transcript, which otherwise renders as an idle terminal. Deliberately NARROWER than the cap's use of the same fact: it upgrades `quiet` only, never overriding `asking`, `awaiting` or a manual mark-unread, because those are things for the user to read and "working" would bury them — and the question branch returns before the upgrade is reachable, so a prompt you are looking at cannot start breathing. Expect the dot and the cap to disagree in one direction as a result: a row can show the solid unread dot while the cap refuses to reclaim it. Both statements are true; they answer different questions.
  - **The fifth marker is NOT a liveness state.** **Two** kinds of live terminal have no transcript Switchboard can attribute to them, and `lib/rowIdentity.ts` is the single predicate for both: a provisional Codex PTY (`PtyState.provisional` — never matched to a rollout; see the Multi-agent section), and a Claude PTY carrying `PtyState.parkedJob` with nothing indexed under its id. Both are excluded from `resolveLiveState` by `lib/rowIdentity.ts#resolveRowLiveState` — the single gate-then-resolve composition that all three of App's consumers go through (the rail rows, the Live tally, the read/unread toggle), so the exclusion can no longer be omitted at one of them the way it once was — and render `.sb-dot.unlinked`, which shares the exact hollow cobalt treatment with `.sb-dot.quiet`. Liveness is read off a transcript, and an unlinked terminal has no transcript known to be its, so resolving any of the four `LiveState` values would describe someone else's conversation. Hollow means nothing linked is unread here; it is presentation reuse, not a resolved `quiet` claim. The Live tally therefore keeps its own `unlinked` bucket — calling a terminal you may be actively typing in "idle" is the misreport this exists to prevent — and pin / rename / details / mark-unread are **hidden**, not merely gated, in both the ⋮ menu and the pane header (`PaneHeader`'s `unlinked` prop drops the pin and renders the title as plain text rather than the info button): persisting anything under an id that may never name a real conversation would orphan, and a control that silently does nothing is worse than an absent one. `lib/rowIdentity.ts#displayTitleForRow` is the single title derivation for both the rail and the pane, so the header cannot name one thing while the row names another.
    They differ only in the preview slot, because they differ in *why* they are empty. An unbound Codex terminal is waiting on a first turn that normally arrives, so it reuses the ordinary italic `No messages yet` — indistinguishable from a new Claude row beside it, which is the truth of the moment. A parked-agent terminal is empty *permanently*, so it titles itself with the agent's own name and states `Terminal only — work is in a background agent`.
    `pty/claudeParkedJobs.ts` supplies `parkedJob` by watching Claude's session registry for its `parkedJobId` marker — which means only that the session **launched** an agent (it is never cleared, not on leaving Agent View nor when the agent ends), so the marker alone must never be read as a state. Pairing it with "has no indexed conversation" is what makes it usable, and re-deriving that every pass is what makes the row correct itself the moment the session writes a transcript. `sessions/claudeJobs.ts#readBgJobName` supplies the title.
  - **Manual read/unread.** `useSeen` also holds an `unread` override map (sessionId → markedAt); `resolveLiveState`'s `manualUnread` arg forces **`awaiting`** (the solid dot) for a finished conversation — or **`asking`** (the pulse) for one blocked on your reply (`awaiting_input`), so marking a question-state unread returns it to pulsing — beating both `lookingNow` and the seen timestamp. Set it three ways: **`⇧⌘U`** (toggles the selected conversation); **Option+click** — on a live row in the left pane, or anywhere in its live terminal — which **always marks unread, never toggles**; or a row's **⋮ menu**. It **auto-expires** once a newer turn lands (`turnEndedAt > markedAt`, derived — no mutation), and is cleared by `markRead`: an explicit toggle, **selecting** the conversation (the seen-effect calls `markRead`, not just `markSeen`), or **engaging** it (a click or keystroke in the pane body, via `MainPane`'s capture-phase listener; scrolling doesn't count).
    - *Option+click wiring:* `ConversationRow`'s `onClick` branches on `e.altKey` before its live/non-live dispatch and returns without navigating; the terminal twin is a dedicated capture-phase `mousedown` listener on the `TerminalView` host (`e.altKey && e.button === 0` → `markUnread`) whose `stopPropagation` is **load-bearing** — it beats `MainPane`'s bubble-phase engage→`markRead` *and* xterm's own mouse handling, and `manualUnread` beating `lookingNow` is what makes the dot go solid even while the conversation is open+focused.
    - *⋮ row menu* (`TallyRail`, the per-row vertical 3-dot — **replaced the old right-click context menu**) offers **Pin/Unpin** and **Session details…** (on every row, live or not), the read/unread item, plus — on a live row only — **Stop session** (kills the session), and — on a not-live row only — **Resume** (spawns + focuses via `App.resumeSession`→`resume`). It opens on **click-to-toggle** *or* **right-click-at-cursor**, and is dismissed by an outside click, **Esc**, or a **rail scroll** (the scroll listener is scoped to the **rail body**, not document-wide, so scrolling the transcript doesn't close it).
  - **Timestamps.** Rows + header show `relTime(lastActivityAt ?? mtime)` (mtime is bumped by resume/metadata writes, so it isn't true last activity).
  - **Carryover demotion.** `resolveLiveState` demotes an `in_progress` turn whose `lastActivityAt` predates the live process's `PtyState.startedAt`: it belongs to a prior, now-dead run — you quit/End the app mid-turn (which writes *no* sentinel, unlike Esc), then **resume**, and the new process just replays history and idles at the prompt (without this it would breathe forever). Anything the current process actually does is stamped after `startedAt`, so genuine work — including a long-running tool — is never demoted.
  - **Known gaps:** a Claude turn **blocked on a permission prompt** (nothing on disk distinguishes it), and `claude` **crashing while its wrapping shell survives** with no resume (there the turn postdates `startedAt`) — both still read as *working*. Codex permission prompts are covered for Switchboard-owned live PTYs by the explicit OSC path above.

- **Math (`lib/mathDelimiters.ts` + `MathBlock.tsx`):** both agents write math, and both use all four delimiter families — `\(…\)` / `$…$` inline and `\[…\]` / `$$…$$` display. `remark-math` reads only the dollar forms, so `normalizeMath` rewrites the LaTeX ones onto them, **length-preservingly** (each substitution is two characters for two). Source offsets computed against the rewritten text still index the original, which lets the table copy button preserve its original Markdown. Selection-copy reads semantic content instead of slicing source offsets. **Any change here must preserve length.** Detection is opt-in per block: nothing is math unless the block holds a **display block whose delimiters sit alone on their own lines**, because these delimiters overwhelmingly mean other things in coding prose (`\[DEBUG\]` is an escaped literal bracket, `sed`/`jq` are full of `\(…\)`, and `$PATH` is everywhere). Single `$` is admitted only when the block wrote its *display* math as `$$` — structural evidence of which convention the block is using, so a `\[…\]`-style block's bare `$` stays a shell sigil (see the fail-closed note in [gotchas.md](gotchas.md)). Fenced, indented, and inline code are excluded from detection as well as rewriting — by **overlap**, not containment, so a pair that starts inside a code span and ends outside it is still rejected — and a fenced ```latex sample stays visible source. Two details the offsets depend on: the rewrite buffer is built with `split('')` (UTF-16 code units) to match the offsets, never `Array.from` (code points), which one emoji before a formula would desynchronize; and display delimiters are paired in a **single pass**, since rescanning per unmatched opener is quadratic. Rendering is **KaTeX, dynamically imported** — it is the largest thing this view could pull in and math is rare, so it is not in the startup bundle; until it resolves (or forever, if it fails) each formula shows its LaTeX source, which is what the view showed before. `output: 'html'` drops KaTeX's parallel MathML tree: that halves the node count and leaves ONE text representation, where the default makes `textContent` read a formula three times over and corrupts the copy walk. **KaTeX lays glyphs out in visual, not reading, order** — a fraction emits its denominator first — so the rendered subtree carries `data-md-skip` (the existing "on screen but not source" marker) and the LaTeX rides beside it in a visually-hidden `.md-math-tex` span; the copy walk therefore collects the source and never the scrambled glyph text. Parse failures are caught and fall back to muted mono rather than KaTeX's lenient mode, which is inconsistent (it flags some failures and silently mis-renders others) and whose error styling would collide with the transcript's use of red.
- **Selection copy (`lib/mdCopy.ts` + `lib/mdCopyDom.ts`):** the DOM adapter builds semantic nodes and per-leaf selection windows in rendered order; the pure serializer decides which formatting survives. A complete component retains Markdown only when selected non-whitespace content lies beyond **either** end. Exact and partial selections are bare; nesting is independent, and context crosses source blocks and speaker sections. No source-substring search or outward widening is used. Inline list gaps are content, while block-layout newlines are excluded. Formatting eligibility is computed before adjacent equivalent retained spans are combined; round-trip checks verify the resulting text and style coverage. Both formats preserve selected whitespace and code indentation. Plain text disables styling, while retaining structural lists and dividers. `rehypeCopyMetadata` preserves code language identifiers; link and image metadata are carried explicitly, without annotating every element with source offsets.
  - **Structural exceptions:** complete items in multi-item selections keep bullets/numbering/task state; partial items and isolated exact items do not. Tables own all pipes and separator rows, never individual cells. Cell completeness requires active selection as well as complete contents, so an unselected empty boundary cell cannot turn a partial grid into a Markdown table. A whole table with selected non-whitespace context on either side becomes Markdown; other selections preserve their ragged grid with tabs/newlines, with nested styles still evaluated normally in Markdown mode. Multi-cell fields containing tabs, newlines, or quotes use double-quote encoding; single cells remain unquoted. A rendered or fallback formula is atomic LaTeX, with delimiters governed by the same surrounding-context rule. Image labels can be sliced; footnote text follows rendered order without importing unselected definitions.

Clamped results contribute only their displayed prefix, measured at copy time against wrapped-line geometry; ordinary scrolling is not an exclusion. Whole displayed tool blocks with selected non-whitespace context on either side gain labels and Markdown fences, while exact/partial selections stay bare. Multiple included speaker sections gain labels and `---` separators. Generated labels never influence formatting eligibility. Empty eligible selections suppress native copying without replacing clipboard contents, preventing hidden text from leaking through a fallback.
